Running `make check-desktop` (and therefore full `make check`) from this session's Bash tool fails with `failed to run 'cargo metadata' ... No such file or directory (os error 2)`, even though a local Rust toolchain was installed via `rustup` during TK-008 and `~/.cargo/bin/cargo` exists on disk. `echo $PATH` in this tool's shell does not include `~/.cargo/bin` — unlike an interactive terminal session, it does not source `~/.cargo/env` from a shell profile. Confirmed workaround for one invocation: `export PATH="$HOME/.cargo/bin:$PATH"` before running `make check-desktop` — it then builds and bundles successfully, matching TK-008's original verification exactly. This is a per-tool-invocation environment quirk on this development machine, not a regression in the repository's own build configuration; GitHub Actions' Rust setup step configures its own runner PATH independently and is unaffected (confirmed by the real passing `check` run on both `macos-latest` and `windows-latest`, see RSK-002).
