Encountered directly while formatting `src/backend/core/tests/integration/test_desktop_channel_session.py` (TK-045): this project's pinned `ruff` (`ruff 0.16.5`, confirmed via `uv run ruff --version`), when run as `ruff format` against `except (asyncio.IncompleteReadError, TimeoutError):`, rewrites it to `except asyncio.IncompleteReadError, TimeoutError:` — dropping the parentheses around the exception tuple, which is invalid Python 3 syntax (Python 2's `except type, value:` form). Confirmed this is genuinely broken, not a misread diff: `ast.parse()` on the resulting file raised a `SyntaxError`, and re-running `ruff format` directly (not just reading its `--check` diff) reproduced the same rewrite deterministically.

Workaround: avoid an inline multi-element exception tuple literal directly in an `except` clause. Naming the tuple as a separate constant first (e.g. `_TRANSPORT_FAILURE_ERRORS = (asyncio.IncompleteReadError, TimeoutError)`, then `except _TRANSPORT_FAILURE_ERRORS:`) sidesteps the bug — `ruff format` leaves that form alone.
