# Structural evolution signals

Direct inspection of `src/backend/core/src/corytm/` on 2026-09-01 confirms the flatness `docs/technical/architecture.md`'s Structural Evolution section describes is real, not aspirational: `engine/` holds three single-class Pydantic model files (`clip.py`, `track.py`, `project.py`), each just field declarations plus `ConfigDict(frozen=True)` — no editing behavior, commands, history, persistence, or repository code anywhere. `runtime/` holds three files already seeded toward distinct concerns — `transport.py` (wire framing), `session.py` (process-spawn orchestration), `projection.py` (pure Engine→wire conversion) — but each is still small (under 35 lines) and single-purpose. No `models/`, `services/`, or `repositories/` subdivision exists anywhere in either subpackage. This matches the repository-structure architecture audit already recorded in `docs/project/status.md`: no repository evidence ever made a finer-grained target shape binding, and `CLAUDE.md` §8's anti-premature-abstraction rule already governs correctly at this file count.

Concrete signals that would justify reconsidering Engine's flatness: editing/command behavior beyond field validation, undo/history, a persistence or repository boundary, or multi-file orchestration actually appearing in `engine/`. None of these exist yet.

Concrete signals for Runtime: `session.py`, `transport.py`, or `projection.py` each growing multiple distinct responsibilities internally, or a fourth materially distinct concern appearing alongside projection/session/transport. None of these exist yet.

One transition of this kind has already happened, as real precedent rather than a hypothetical: the Native Audio Runtime's production-root/`tests/` split (documented in `docs/technical/architecture.md`'s "Native Audio Runtime Source Layout" section). The trigger there was concrete and already crossed — `src/backend/audio/` had grown to 11 files mixing shippable production code with one-off proof/ctest executables, with no prior repository artifact stating a convention for the distinction. That is the scale/shape of evidence that should trigger a similar restructuring in Engine or Runtime — not file count alone, and not resemblance to the illustrative models/services/repositories vocabulary in isolation.
