# ADR-002 — Python Application Core and Native C++ Audio Runtime as Separate Processes

Status: accepted

## Context

The native audio runtime (Tracktion Engine + JUCE) and the Python application core could run in one process or as separate processes.

## Decision

The Python application core and the native C++ audio runtime run as separate processes, communicating through a narrow, versioned local protocol. The transport is not yet decided. The native runtime exposes a limited, application-oriented interface rather than exhaustive bindings to Tracktion Engine.

## Consequences

The native process has an independently manageable lifecycle — it can be started, stopped, or restarted somewhat independently of the Python application core. A defined local IPC protocol and a synchronization layer (Runtime) are required. Cross-process communication is real engineering surface area an in-process design would not have. This decision establishes process topology and lifecycle only — it does not itself decide how or whether musical/project state is reconstructed across a restart; that is governed by ADR-001.

## Notes

This process boundary is what makes Corytm Engine, Runtime, and Native Audio Runtime distinct components. Related to ADR-001 and ADR-003.
