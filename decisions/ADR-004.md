# ADR-004 — Dorian Operates Through Trusted Semantic Application Capabilities Shared With Human Editing

Status: accepted

## Context

Dorian could be given direct native/Tracktion access, or be constrained to the same application/domain capabilities the human UI path uses.

## Decision

Dorian operates only through trusted semantic application tools and services — the same application/domain capabilities available to human-driven UI actions. Dorian must never generate C++ as an execution mechanism, make arbitrary Tracktion calls, bypass application/domain boundaries, or execute arbitrary shell commands as a normal product capability. Human UI actions and Dorian actions are intended to go through the same application/domain API, so editing business logic is not duplicated per caller. The model proposes actions; trusted application code authorizes and executes them.

## Consequences

Every new capability Dorian needs requires a defined, tested semantic tool rather than ad hoc access — ongoing engineering investment, not a one-time cost. Dorian's capability surface is exactly as large as the deliberately exposed tool set. Human-triggered and Dorian-triggered edits are covered by the same validation path, since there is only one path.

## Notes

This boundary protects the canonical state established in ADR-001 and crosses the process boundary established in ADR-002. It is a binding architecture/security principle.
