# ADR-005 — Local-First Product and System Direction

Status: accepted

## Context

Corytm could be built cloud-authoritative — project state owned by a server, the local app a client — or local-first, with project state and resources living locally and cloud capabilities as a later, non-authoritative extension. Corytm's native audio foundation (ADR-002, ADR-003) requires local audio/MIDI device access and local plugin hosting.

## Decision

Corytm's core project editing and local operation are local-first. Local project state and local resources are primary for this domain, and core local operation must not depend on server-authoritative project state. Future cloud, collaboration, synchronization, or remote capabilities may introduce server-side state where appropriate, but must extend the local-first core rather than replace it.

## Consequences

Core editing and local operation function without a server dependency. Any future collaboration or sync feature is designed as an extension of local-first, not a replacement for it. Cloud-specific code must not become a dependency of the local-first domain. Persistence implementation, synchronization, conflict resolution, and collaboration architecture all remain unresolved.

## Notes

This is a deployment/data-locality decision, distinct from the internal Python/C++ topology in ADR-001/ADR-002.
