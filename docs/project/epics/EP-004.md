# EP-004 — Alpha Platform Foundation

Status: done
Milestone: MS-002

## Objective

Establish the two foundational pieces ADR-006 and ADR-007 just decided — the Tauri desktop shell and the Protobuf/local-loopback-socket transport between the Python core and the Native Audio Runtime — as minimal, proven, working plumbing, mirroring EP-001's own "prove the toolchain before building on it" approach for Pre-alpha.

## Scope / Out of scope

In scope: a Tauri 2 application wrapping the existing `src/frontend/desktop/` React UI, packaged and launchable on macOS and Windows; Tauri's sidecar mechanism spawning the existing Python core and Native Audio Runtime as managed child processes; an explicit shutdown protocol given Tauri's documented sidecar-kill limitation (ADR-006's Consequences); a minimal Protobuf schema under `src/schemas/` with generated C++ and Python bindings; a minimal end-to-end proof that a command sent from Python reaches the native process over the ADR-007 transport and a resulting event flows back, authenticated per ADR-007's per-launch-secret pattern.

Out of scope: any real Corytm Engine domain model or musical/product behavior (Track, Clip, Note, Plugin, Automation, or any other product concept); any real Dorian capability or UI; UI design system or real screens; the concrete protocol/schema messages a real product would need (still unresolved per `docs/technical/architecture.md`'s Unresolved section — this Epic proves the plumbing with minimal, illustrative messages only); persistence, cloud/sync, or provider-mapping work (all still unresolved).

## Acceptance criteria

A Tauri 2 application builds and launches on both macOS and Windows, hosting the existing frontend. It spawns the Python core and Native Audio Runtime as child processes and can cleanly shut both down. A Protobuf-defined command, sent from the Python core over the ADR-007 transport, is received and acknowledged by the native process, with an event flowing back — proving both ADR-006 and ADR-007 work in practice, not just on paper. No Corytm product/domain functionality is implemented anywhere.

## Dependencies

None (MS-002's own dependency on ADR-006/ADR-007 being decided already governs this Epic).

## Notes

This Epic is deliberately scoped like EP-001 (Engineering Foundation): prove the two new architectural pieces work before any real product path is built on them. Feature/Task-level detail is intentionally deferred per `docs/project/plan.md`'s Rolling-Wave Planning — it will be refined when a session begins executing this Epic, the same way EP-001 and EP-003 were refined only once work on them actually began.

**Closed:** all four Features are done and proven cross-platform by real, independently-confirmed GitHub Actions evidence, not local reasoning alone — FT-007 (Tauri desktop shell, builds and launches on macOS and Windows), FT-008 (Protobuf schema/codegen, both C++ and Python bindings), FT-009 (the ADR-007 transport round trip, Python↔native over the loopback socket), FT-010 (Tauri sidecar spawn/communicate/explicit-shutdown). One Acceptance-criteria detail was narrowed during FT-010's own DISCOVER, before implementation, not after: neither the Python core nor the Native Audio Runtime has an actual entry point to spawn yet, and `docs/project/plan.md` itself scopes real packaging/frozen-executable work to Beta, not Alpha — so FT-010 proved the spawn/communicate/explicit-shutdown *mechanism* against a minimal placeholder script (`src/backend/core/sidecar_proof.py`) rather than the real Python core and Native Audio Runtime processes named in this Epic's original Acceptance criteria text above. This mirrors FT-008/FT-009 proving the ADR-007 transport with an illustrative `ProofMessage` rather than real product messages, and is recorded here rather than silently reinterpreted: genuinely spawning the real Python core and Native Audio Runtime as managed sidecars needs each to have an actual entry point/executable first, which belongs to whichever future Milestone/Epic first needs a running Python core producing real sound. Both ADR-006 and ADR-007 are proven working in practice. `RSK-002`, `RSK-003`, and `RSK-004` are all closed.
