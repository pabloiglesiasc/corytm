# EP-006 — First Edit: Incremental Clip Move Through a Live Native Session

Status: active
Milestone: MS-002

## Objective

Extend MS-002's proven synthetic, one-shot, full-snapshot slice (EP-005) toward genuine incremental editing: Corytm Engine's first real edit operation and its wire command/event shape, proven end to end against a Native Audio Runtime process that keeps its materialized Tracktion `Edit` alive across multiple commands rather than exiting after exactly one. This is the shared mechanism both of MS-002's still-unreached Outcome halves depend on — a user editing manually through Desktop and Dorian performing a semantic edit are both, at the application boundary, sending an edit command distinct from resending the whole project — so proving it once here removes it as a blocker for either.

The illustrative example already named in `docs/technical/architecture.md`'s "Engine Services and Incremental Updates" section — "a command to move a clip producing a 'clip moved' event" — is made real by this Epic, at the smallest scope that proves it, not the general case.

## Scope / Out of scope

In scope: exactly one edit operation — moving an existing clip's start position — proven through three increments, mirroring EP-005's own "prove one increment, then the next" shape: (1) Corytm Engine's own edit operation on the canonical `Project`/`AudioTrack` model, a `MoveClipCommand`/`ClipMovedEvent` wire schema addition, and a pure projection function, proven in isolation (no native/runtime wiring); (2) the Native Audio Runtime accepting and applying that edit to an already-materialized, still-live `tracktion::Edit` — a genuinely new native behavioral surface, since `native_runtime` currently exits after exactly one command; (3) a real Python entry point sending a sequence of two commands (materialize, then move) over one long-lived `native_runtime` connection, with an automated cross-language test proving the second command's effect is reflected in a subsequent deterministic re-render.

Out of scope (revisit only with concrete implementation evidence a slice this small cannot avoid it): any other edit operation (add/remove track or clip, delete, resize, split, gain, fades); persistence of a project across process restarts; project create/open UI or any other Desktop UI work; Dorian and its semantic-tool boundary (ADR-004) — this Epic proves the application-layer command shape both future paths will call into, not Dorian itself; real-time/live audio-device playback while editing; concurrent or multi-client access to one native process; a generalized command-dispatch/oneof envelope beyond what two concrete command types require.

## Acceptance criteria

A real edit intention — moving a clip — expressed as a Corytm Engine operation produces a new, fully validated canonical `Project` (the prior `Project` unchanged). The same intention, expressed as a `MoveClipCommand` wire message, is applied by the Native Audio Runtime to its already-live materialized `Edit` (not a fresh rebuild from a resent full snapshot), and the resulting re-render's deterministic, measurable output reflects the moved clip. Both are proven by automated tests; the native/live-session half is confirmed by real, independently-verified cross-platform CI evidence (macOS and Windows), consistent with every prior native-behavioral surface this project has proven (RSK-005/006/007).
