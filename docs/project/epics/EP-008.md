# EP-008 — Dorian's First Semantic Edit

Status: done
Milestone: MS-002

## Objective

Prove ADR-004's trusted-capability boundary for real: Dorian never touches Corytm Engine or the Native Audio Runtime directly, only a defined, tested semantic tool that validates a model-proposed edit before trusted application code authorizes and executes it. This closes MS-002's second, harder-to-de-risk Outcome half (Dorian performing a real semantic edit with an observable effect on sound) by exposing EP-006's already-proven move-clip mechanism — Corytm Engine's `with_clip_moved` operation and the live native session — through Dorian's first tool, rather than building any new edit operation or native behavior.

## Scope / Out of scope

In scope: exactly one Dorian tool (move an existing clip's start position), its typed tool-call input schema, and the trusted validate-then-execute boundary that calls it through Corytm Engine's existing operation and EP-006's existing live native session — proving the full "model proposes, trusted code authorizes and executes" path end to end with an observable effect on the re-rendered sound.

Out of scope (revisit only with concrete implementation evidence a slice this small cannot avoid it): any real LLM/provider integration or API call; model routing or the Allegro/Virtuoso/Maestro tiers; any Dorian tool other than move-clip; conversational or UI surface of any kind; Desktop UI; persistence of a project across process restarts; any new Engine edit operation or native behavior beyond what EP-006 already proved; multi-tool orchestration or an agent loop; parsing tool-call arguments in any specific third-party provider's function-calling format.

## Acceptance criteria

A move-clip edit proposal, shaped as untrusted tool-call arguments, is validated by trusted application code before it can reach Corytm Engine or the Native Audio Runtime — malformed or invalid input is rejected without executing anything. A valid proposal is authorized and executed through Corytm Engine's existing `with_clip_moved` operation (producing a new canonical `Project`) and applied to an already-live native `Edit` via EP-006's live-session mechanism, with the resulting deterministic re-render reflecting the move. Proven by automated tests. No new native code path is introduced, so no new cross-platform native-behavioral risk is opened — EP-006's own CI evidence already covers the reused live-session mechanism unchanged.

## Dependencies

EP-006 (done) — reuses its `Project.with_clip_moved` Engine operation and `materialize_then_move_clips` live-session mechanism unchanged as the trusted execution path this Epic's tool calls into.
ADR-004 (accepted) — the architectural boundary this Epic makes real for the first time.
