# EP-009 — Desktop Command Channel: A Typed Protocol From Tauri to Corytm Engine

Status: done
Milestone: MS-002

## Objective

Prove ADR-010's Desktop↔Python-core channel for real: give Tauri's Rust core a working, typed, versioned way to send commands to the Python core and receive results back, over a transport that is fully independent of the Python↔Native Audio Runtime one (ADR-007). This closes the one missing mechanism MS-002's manual-Desktop-editing Outcome half depends on — real Desktop UI has nowhere to build on until Rust can reach Corytm Engine at all. Mirrors EP-004's own "prove the mechanism before building product on it" shape, and EP-006's "isolated proof, then combined" increment sequence.

## Scope / Out of scope

In scope: a new, minimal Desktop-facing Protobuf schema and Rust codegen toolchain (mirroring FT-008/TK-009's C++ codegen proof, but for Rust); the second independent loopback-socket transport ADR-010 defines, including Python core opening the new listener and passing its port/secret over the existing sidecar stdout channel, and Rust connecting/authenticating/exchanging one proof-of-mechanism command/event round trip against the real spawned Python sidecar. Proven the same way this project has proven every prior cross-platform mechanism: automated tests, validated locally, closed only on real independently-verified Windows+macOS CI evidence.

Out of scope: any real UI-facing domain command beyond a proof-of-mechanism message (no `CreateProjectCommand` or equivalent yet — that is deliberately deferred to a later Epic, mirroring how FT-008's `proof.proto` preceded FT-011's real `project.proto`); any Desktop UI component, layout, state-management, or rendering choice (`docs/technical/architecture.md`'s Unresolved section); any change to the Python↔Native Audio Runtime transport, schema, or `native_runtime` process; any Dorian/provider work.

## Acceptance criteria

Rust generates and compiles real Protobuf bindings from a Desktop-facing schema under `src/schemas/`, independent of `project.proto`'s native-facing envelope. The Python core sidecar (the real `corytm` entry point, not a throwaway proof script) opens a second loopback listener with its own port and random per-launch secret, distinct from whatever it later uses to spawn/authenticate the Native Audio Runtime, and communicates that port/secret to Rust over the existing sidecar stdout lifecycle channel. A Rust client connects, authenticates with the secret, and completes one real command/event round trip against the real spawned sidecar process. No native/schema code on the Python↔C++ side changes. Proven by automated tests (a `cargo test` mirroring `transport_proof.cpp`/`test_transport_proof.py`'s shape), closed only once independently confirmed on a real, passing cross-platform (macOS + Windows) GitHub Actions run — this Epic introduces a genuinely new cross-platform surface (Rust as a socket client, a new Rust protobuf/`protoc` toolchain), so this project's own established practice (RSK-002 through RSK-009) applies: no closing on local verification alone.

## Dependencies

ADR-010 (accepted) — the architecture this Epic makes real. ADR-006/FT-010 (done) — Tauri sidecar spawn/shutdown, reused unchanged. ADR-007/FT-009 (done) — the transport pattern this Epic mirrors for a second, independent boundary.
