# EP-011 — Real Desktop Project Persistence

Status: active
Milestone: MS-002

## Objective

Realize ADR-011's local JSON persistence format as real project create/open/save capability, closing MS-002's last unaddressed manual-editing thread: EP-010 proved one hardcoded move against an in-memory fixture project, not real project creation, opening, or persistence. Mirrors this Milestone's own established shape (EP-009 → EP-010: prove the mechanism, then build real UI on top of it) applied to persistence specifically.

## Scope / Out of scope

In scope, as distinguishable increments — not necessarily separate Features (see Notes):

1. Corytm Engine gains a real persistence module (`corytm.engine.persistence`) implementing ADR-011's versioned local JSON envelope: `save_project`/`load_project`.
2. The Desktop channel (ADR-010) carries real `CreateProjectCommand`/`SaveProjectCommand`/`OpenProjectCommand` commands and their result events, added to `project.proto`'s existing `Command`/`Event` oneof per ADR-011, backed by the persistence module and — for Open — the already-proven `MaterializeProjectCommand`/native-render path.
3. Tauri resolves a real filesystem path via a native OS file dialog (`@tauri-apps/plugin-dialog`) and a minimal Desktop UI lets a human create, save, and open a project through actual UI controls.

Out of scope (mirrors ADR-011's own explicit deferrals): any track/clip authoring UI beyond the existing move-clip fixture trigger; project-bundle/directory formats or external resource references; multiple concurrent projects or windows; autosave, crash recovery, or undo-history persistence; migration tooling or any backward-compatibility guarantee for Alpha-era files; cloud/sync persistence; Dorian/provider wiring; any visual/UX design investment beyond function.

## Acceptance criteria

A human can launch the real Desktop app, create a new project, save it to a real file through a native save dialog, and open a previously-saved file through a native open dialog — observing the reopened project's genuine re-render (sample count, peak amplitude) through the Native Audio Runtime — proven end to end by a combination of automated tests (per-increment, mirroring this Milestone's established practice) and, where real native-dialog/process behavior can't be exercised headlessly, a human confirmation step distinct from and in addition to automated evidence.

## Dependencies

EP-009 (done) — the Desktop channel this Epic extends. EP-010 (done) — the one existing real Desktop command (`MoveClipCommand`) this Epic's protocol change must not regress. ADR-011 (accepted) — the persistence format this Epic realizes.
