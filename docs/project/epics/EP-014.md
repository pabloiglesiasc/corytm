# EP-014 — Real-Time Playback Foundation

Status: active
Milestone: MS-003

## Objective

Give the Native Audio Runtime real-time audio-device playback for the first time, and expose it as a real Play/Stop transport a human can use from the actual Desktop app — extending the runtime beyond its current design, where every path (EP-005 through EP-012) only ever renders an `Edit` offline to a WAV file via `EditRenderer::render`, with the `DeviceManager` explicitly disabled (`HeadlessEngineBehaviour::autoInitialiseDeviceManager() { return false; }`, `src/backend/audio/native_runtime.cpp`). This is the foundational mechanism `docs/product/roadmap/alpha.md`'s "Real-time audio-device initialization/output," "Live play/stop/pause transport," "Playhead and real-time position," and "Transport state reflected coherently in UI" entries all depend on, and the specific gap `docs/project/plan.md`'s Alpha Exit criteria names as not satisfied by offline rendering alone.

## Scope / Out of scope

In scope: opening a real audio output device through Tracktion Engine's `DeviceManager` for the first time; driving an already-materialized, already-live `Edit`'s real-time transport (play, stop) against that device rather than through `EditRenderer`'s offline path; reading live playback position while playing; extending the existing Desktop-channel/native-session command protocol (`project.proto`'s `Command`/`Event` oneof, the multi-command `native_runtime` session loop from EP-006/EP-011) with Play/Stop commands and position feedback; a minimal Desktop UI Play/Stop control and playhead display, reusing the existing card-layout scaffold FT-025 already established (not a workspace/information-architecture redesign — `docs/technical/architecture.md`'s Unresolved section already flags that as a separate, not-yet-decided piece of work). Mirrors EP-005/EP-006's own "prove the native mechanism in relative isolation, then wire it end to end" shape.

Out of scope (revisit only with concrete implementation evidence a slice this size cannot avoid it): seek/arbitrary playhead positioning, loop-region playback, pause (as distinct from stop), metronome/count-in, sample-rate/buffer configuration, audio-device input/output selection or configuration, audio-device hot-plug/recovery, master output monitoring/metering, clipping indication, any multi-track materialization change (still `project.tracks[0]`-only, unchanged by this Epic), and any Desktop workspace/information-architecture redesign. All are separate `docs/product/roadmap/alpha.md` entries in the same Real-Time Audio & Transport category, left for later work under MS-003.

## Acceptance criteria

The Native Audio Runtime opens a real audio output device via Tracktion Engine's `DeviceManager` and, given an already-materialized `Edit`, starts genuine real-time playback through it on a Play command and halts it on a Stop command — proven by a human-only local audible confirmation as the acceptance boundary automation cannot substitute for (mirroring EP-005's own precedent), since CI runners are not expected to expose real audio hardware. A human can launch the real Desktop app, open or create a project with a clip, click Play, hear real-time audio-device output, see a live playhead reflecting real-time position, and click Stop to halt it — the full vertical path (Desktop UI → Desktop channel → Python core → Native Audio Runtime → real device → sound), not a backend-only proof.

## Dependencies

EP-005 (done), EP-006 (done), EP-011 (done), EP-012 (done) — reuses `project.proto`'s `Command`/`Event` oneof, the native multi-command session loop, the Desktop channel (ADR-010), and the existing Tauri/React Desktop app unchanged as the starting point this Epic extends.
