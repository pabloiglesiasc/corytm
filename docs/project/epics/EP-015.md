# EP-015 — Testing Policy, Layout, and Local Validation Tooling

Status: done

## Objective

Consolidate Corytm's testing architecture and local validation workflow, per the user-approved testing-architecture-and-policy review conducted 2026-09-03: adopt a tiered validation policy built on an exact-input invalidation principle, migrate Python's test layout to a structural production/test separation, and wire already-proven local caching mechanisms into local development — all without weakening any existing quality guarantee or acceptance-evidence requirement. The goal is the same or stronger confidence with materially less redundant execution time, never less evidence.

## Scope / Out of scope

In scope: a new canonical `docs/technical/testing.md` and a minimal `CLAUDE.md` §7 pointer to it; excluding `live_llm` from `check-python`'s default pytest invocation; local `sccache`/CMake compiler-launcher wiring for `check-native`/`check-desktop`, mirroring the mechanism `.github/workflows/check.yml` already proves works; a lockfile-stamp-gated install mechanism for `check-frontend` (CI keeps unconditional `npm ci`); migrating every colocated Python unit test under `src/corytm/**` into `src/backend/core/tests/{engine,dorian,runtime}/` (inspected individually, not classified mechanically by filename) and relocating the existing cross-component tests under `src/backend/core/tests/` into `src/backend/core/tests/integration/`; a new narrow `.claude/skills/testing-review/SKILL.md` operationalizing the new policy.

Out of scope: an automatic test-result fingerprint/cache ledger; automatic dependency-graph affected-test selection; an expanded pytest marker taxonomy beyond `transport`/`live_llm`; Cargo debug/release profile unification; frontend/Tauri double-build deduplication (`npm run build` running twice); any change to `.github/workflows/check.yml`'s own behavior or to CI's `npm ci` semantics; any change to Corytm Engine/Runtime/Native Audio Runtime/Dorian/Desktop product behavior; any weakening of an existing quality gate or acceptance-evidence requirement; a Hatchling packaging exclude added merely to compensate for the old test layout (only if a concrete, independent packaging reason remains after the migration).

## Notes

No Milestone: this is cross-cutting build/test-harness work, not a product-outcome slice of MS-003, mirroring EP-007's own relationship to MS-002 (`docs/project/epics/EP-007.md`). Approved for implementation by the user on 2026-09-03 following a consultative testing-architecture review conducted earlier the same session (measured local/CI timings, real command-graph tracing, and a full test inventory — not itself a PMO record, since it was analysis only); this Epic is that review's approved implementation, with several explicit user overrides to the review's own recommendations (notably: migrate the Python test layout rather than keep it colocated, and use a lockfile-stamp mechanism rather than plain `npm install` for the frontend-install optimization).
