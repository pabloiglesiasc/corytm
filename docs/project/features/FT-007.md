# FT-007 — Tauri Desktop Shell

Status: done
Epic: EP-004
Milestone: MS-002

## Objective

Establish a Tauri 2 application under `src/frontend/desktop/` that hosts the existing React/TypeScript frontend unchanged, building and launching locally — proving ADR-006's chosen desktop shell technology works in practice before any sidecar process orchestration (a future EP-004 Feature, not yet created) or product UI is built on top of it, mirroring EP-001's "prove the toolchain before building on it" approach.

## Acceptance criteria

A Tauri 2 project exists under `src/frontend/desktop/` alongside the existing frontend, its CLI consumed as the npm devDependency `@tauri-apps/cli` rather than a separately-installed global tool. `npm run tauri build` produces a working application bundle; `npm run tauri dev` launches it locally hosting the existing frontend's current content unchanged — verified by direct human observation of the rendered window during TK-008, not merely a process-level check. The root Makefile's quality interface builds the shell as part of `make check`. No sidecar process spawning, no Protobuf transport, and no real product UI is implemented.

## Dependencies

None.

## Notes

Cross-platform CI validation (the shell actually building on both macOS and Windows runners) is expected to follow the EP-001/EP-002 precedent: this Feature proves the toolchain locally first; confirming a passing cross-platform CI run requires a human git push (`CLAUDE.md` §10) and is tracked as a follow-on step rather than something this Feature's own Task can confirm end-to-end. RSK-002 tracks the risk this Feature is the first direct test of.
