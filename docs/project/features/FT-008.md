# FT-008 — Protobuf Schema & Bindings

Status: active
Epic: EP-004
Milestone: MS-002

## Objective

Establish `src/schemas/` as a real, buildable Protobuf schema per ADR-007, with generated C++ (CMake-vendored) and Python (uv-managed) bindings produced from a single neutral `.proto` source — proving ADR-007's schema/codegen toolchain works in practice on both sides of the Python↔Native Audio Runtime boundary before any socket transport, authentication, or sidecar process orchestration is built on top of it. Mirrors FT-007's "prove the toolchain before building on it" approach for the other EP-004 foundation piece.

## Acceptance criteria

A `.proto` file exists under `src/schemas/` defining one minimal, explicitly illustrative message carrying an explicit schema-version field, per ADR-007's "each message carries an explicit schema version" requirement — not a real product command or event. CMake vendors Protobuf (`FetchContent`, mirroring the existing JUCE/Tracktion Engine pattern already in `src/backend/audio/CMakeLists.txt`) and generates C++ bindings from the schema as part of `check-native`; a native proof constructs, serializes, and deserializes the message and verifies round-trip equality, including the version field. The Python core generates bindings from the same `.proto` via a uv-managed codegen step (a dev-only codegen tool; `protobuf` itself is added as a `[project]` runtime dependency per ADR-007's "the only new runtime dependency is the `protobuf` package on the Python side"); a Python proof performs the same round-trip. `make check` builds and validates both sides. No sidecar process spawning, no socket transport or authentication, and no real product message content — those remain out of scope for future EP-004 Features per EP-004's own Scope/Out of scope.

## Dependencies

None (FT-007 is done but is an unrelated toolchain proof; no ordering dependency exists between them beyond both being EP-004 foundation pieces).

## Notes

Recommended by the prior session (`docs/project/status.md`) as the next EP-004 Feature to prove — ahead of sidecar/shutdown-protocol work — because RSK-002 named Protobuf/CMake codegen as the other still-unproven toolchain risk alongside Tauri (now fully proven cross-platform), and because the sidecar/shutdown-protocol work is inherently more complex and depends on this schema existing first.

**Reopened:** this Feature was previously marked `done` on the strength of a macOS-only local proof, with the real cross-platform confirmation explicitly flagged as pending (see TK-009's original "Unverified" note). That pending Windows CI run then genuinely failed — a real `LNK2038` C-runtime-library mismatch, plus a ~53-minute job duration regression — proving the C++ side was not actually cross-platform-proven despite the Knowledge impact section's "fully proven on both toolchain halves" language, which was premature. Per `CLAUDE.md` §7/§10 this Feature is reopened honestly rather than left marked done against contrary evidence; TK-009 carries the full root-cause diagnosis, fix, and local re-validation. This Feature returns to `done` only once a real Windows CI run confirms the fix (tracked in `docs/project/status.md`).
