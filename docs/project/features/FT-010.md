# FT-010 — Tauri Sidecar Process Spawning & Explicit Shutdown Protocol

Status: active
Epic: EP-004
Milestone: MS-002

## Objective

Prove Tauri's process-orchestration side of ADR-006: spawning a managed child process, communicating with it over stdio, and shutting it down cleanly through an explicit, application-level protocol rather than relying on Tauri's documented sidecar-kill limitation. Completes EP-004's remaining unproven scope alongside FT-007 (shell), FT-008 (schema/codegen), and FT-009 (transport).

## Acceptance criteria

A Rust-side, automated test (`cargo test`, no manual/visual confirmation needed) spawns a Python child process via `tauri-plugin-shell`, waits for it to signal readiness over stdout, sends an explicit shutdown message over its stdin, and confirms the process exits cleanly (exit code 0) — proving the stdin-based shutdown protocol works, in contrast to `CommandChild::kill()`, which ADR-006's Consequences documents as unreliable for a one-file frozen executable. `make check` (or `check-desktop`) exercises this automatically. No frontend/UI, no IPC/capability changes (the spawn happens entirely from trusted Rust backend code, not through the JS-invoke bridge Tauri's capability/ACL system gates — confirmed by reading `tauri-plugin-shell`'s own source: its scope checks live only in the JS-invoked command handlers, not in the `Shell::command()`/`Command::spawn()` Rust API this Task calls directly).

## Dependencies

None (FT-007 done; this Feature only needs the existing Tauri shell, not FT-008/FT-009's schema/transport work).

## Notes

**Scope deliberately narrowed from EP-004's original framing after DISCOVER, not before:** EP-004's Scope text describes "Tauri's sidecar mechanism spawning the existing Python core and Native Audio Runtime" — but neither has any spawnable entry point yet (`src/backend/core` has no application entry point; the Native Audio Runtime has only toolchain-proof executables). Real packaging of a frozen, distributable Python executable — the specific scenario ADR-006's Consequences names as unreliable to `kill()` — is `docs/project/plan.md`'s own explicit **Beta** scope ("packaging/installers"), not Alpha's. Per `CLAUDE.md` §4, that higher-authority phase boundary governs over an Epic's own (necessarily provisional, per Rolling-Wave Planning) scope wording. This Feature therefore proves the *mechanism and protocol* now — spawn, communicate, explicit clean shutdown — against a plain interpreter-invoked script (`src/backend/core/sidecar_proof.py`, deliberately named and scoped as a toolchain proof, mirroring `toolchain_proof.cpp`/`proof_schema.cpp`/`transport_proof.cpp`'s precedent), deferring frozen-executable packaging and the two-sidecar (Python core + Native Audio Runtime) integration to Beta/a later Task once there is real product code to spawn. Also decided during DISCOVER, reading `tauri-plugin-shell`'s own real source rather than guessing: `Shell::sidecar()` (the `externalBin`-bundled-binary API) is the wrong tool for this proof specifically because it requires a pre-built, target-triple-suffixed binary — exactly the packaging investment being deferred; plain `Shell::command()` (an ordinary subprocess spawn, not a bundled sidecar binary) proves the same spawn/communicate/shutdown mechanism without that dependency.
