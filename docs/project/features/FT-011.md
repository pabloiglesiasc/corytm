# FT-011 — Corytm Engine Domain Model and Protobuf Project Schema

Status: active
Epic: EP-005
Milestone: MS-002

## Objective

Establish the minimal canonical Corytm Engine domain model (`Project` → `AudioTrack` → `AudioClip`, timing only) under `src/backend/core/modules/engine/`, a real Protobuf schema for it under `src/schemas/project.proto` (a `MaterializeProjectCommand` carrying the project and a `ProjectRenderedEvent` carrying the render outcome), generated into both C++ and Python bindings, and a pure Runtime projection function under `src/backend/core/modules/runtime/` that converts an Engine `Project` into the wire command — no I/O, no process spawning yet (that is FT-013's concern once the Native Audio Runtime side exists to talk to).

## Acceptance criteria

`Project`, `AudioTrack`, and `AudioClip` exist as minimal Python types under `modules/engine/`, each unit-tested in place per `CLAUDE.md` §8. `src/schemas/project.proto` defines `AudioClip`/`AudioTrack`/`Project`/`MaterializeProjectCommand`/`ProjectRenderedEvent` messages, each carrying an explicit `schema_version` per ADR-002, and is wired into both `check-native`'s CMake codegen (mirroring `proof.proto`/FT-008) and `check-python`'s `uv`-driven codegen. `modules/runtime/projection.py` converts an Engine `Project` into a `MaterializeProjectCommand` with no side effects, unit-tested against representative Engine values. `modules/runtime/transport.py` holds the ADR-007 wire-framing helpers (magic number, length-prefixed read/write), and `tests/test_transport_proof.py` (FT-009) is updated to import them instead of its own hand-duplicated copy, removing that duplication now that a real production implementation exists. `pyproject.toml`'s Pyright `include` and pytest `testpaths` are extended to cover `modules/` (and, once FT-013 adds it, `main.py`) — this is new permanent product code, not another proof script, so it is fully covered by the strict-typing gate `CLAUDE.md` §8 requires. `make check-python` and `make check-native` both pass locally with the new schema in place; `proof_schema`/`proof.proto` (FT-008) continue to pass unchanged.

## Dependencies

None (FT-008's codegen pipeline and `src/schemas/` convention already exist and are reused unmodified).

## Notes

Deliberately excludes any native-side use of `project.proto` beyond generating and linking the C++ bindings (mirroring FT-008's own scope) — materializing a `MaterializeProjectCommand` into a real Tracktion `Edit` is FT-012's job, not this Feature's.
