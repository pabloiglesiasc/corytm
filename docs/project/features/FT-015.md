# FT-015 — Windows Compiler-Cache Routing and Native Target-Graph Duplication

Status: done
Epic: EP-007

## Objective

Make the `check` workflow's Windows job's compiler caching genuinely observable (or document precisely why it cannot be, per mechanism), and remove genuinely safe native compilation duplication across the Tracktion/JUCE-dependent CMake targets — both diagnosed from the real GitHub Actions run, not assumed from the prior optimization session's own expectations.

## Acceptance criteria

- Real `gh run view`/`gh api` evidence (not the user's summary alone) is independently pulled and read for the latest real `check` run, confirming or correcting each of the reported observations (macOS duration/hit-rate, Windows native-deps cache restore, Windows `cmake --build` duration, Windows `sccache --show-stats` compile-request count, cross-target Tracktion/JUCE recompilation) before any fix is designed against them.
- Windows MSVC C/C++ compiler-cache routing: either made observably active, or conclusively shown — via CMake's and sccache's own current, real documentation/issue trackers, not guessed — why it cannot be while keeping the Visual Studio generator, with any confirmed-dead configuration removed rather than left silently ineffective.
- Windows Cargo/Rust compiler-cache routing: diagnosed as far as static log evidence allows; any low-risk, evidence-justified mitigation is applied; anything genuinely undeterminable without a live Windows run is instrumented (not guessed past) so the next real run supplies the missing evidence.
- The native CMake target graph's actual duplicate compilation of Tracktion/JUCE translation units across `toolchain_proof`/`materializer`/`materializer_proof`/`native_runtime` is measured directly from build logs; where consolidating it is genuinely safe (identical compile definitions/standard/linkage across the affected targets), it is restructured into a shared library consumed by all four, with `transport_proof`/`proof_schema`/`project_schema` left untouched since they do not depend on Tracktion.
- A full local `make check` (all five targets) passes end to end after the CMakeLists.txt restructuring, with the native rebuild showing measurably fewer duplicate compiles of the same Tracktion/JUCE translation units and zero new warnings.
- `docs/project/risks.md` and `docs/project/status.md` reflect the empirical findings, including whatever remains genuinely unresolved pending the next real Windows Actions run.

## Dependencies

None — this is a self-contained CI/build diagnosis and fix, not gated on any Epic/Feature currently in flight.
