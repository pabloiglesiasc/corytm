# FT-018 — Dorian's Move-Clip Tool

Status: done
Epic: EP-008
Milestone: MS-002

## Objective

Give Dorian its first semantic tool: a typed, validated move-clip proposal shape and a trusted authorize-and-execute function that is Dorian's only sanctioned path to move a clip (ADR-004) — never a direct call into Corytm Engine or the Native Audio Runtime from anywhere else in `corytm.dorian`. Reuses Corytm Engine's `with_clip_moved` operation and EP-006's live native session unchanged; this Feature adds the trusted boundary in front of them, not a new edit mechanism.

## Acceptance criteria

A move-clip proposal constructed from untrusted, tool-call-shaped input (a raw mapping, as a model's tool call would supply) is rejected by validation — wrong types, a missing field, an out-of-range value, or an unexpected extra field — before any Engine or native code runs. A validly-constructed proposal, executed through the tool's authorize-and-execute function, produces a new canonical `Project` with the targeted clip moved (Engine's own existing validation still applies — an unknown track or clip id is rejected) and drives EP-006's live native session to re-render with the move applied, returning the same kind of `ClipMovedEvent` evidence EP-006 already proves (sample count and peak amplitude reflecting the moved clip). Proven by automated tests, isolated ones for validation and an end-to-end one (`pytest -m transport`) for the full authorize-and-execute path against the real native runtime. No native/schema code changes.

## Dependencies

EP-006 (done) — `Project.with_clip_moved`, `materialize_then_move_clips`, `ClipMove` reused unchanged.
