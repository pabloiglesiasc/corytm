# FT-020 — Desktop↔Python Socket Transport Proof

Status: active
Epic: EP-009
Milestone: MS-002

## Objective

Prove ADR-010's second, independent loopback-socket transport for real: the real `corytm` entry point opens a second listener and hands its port/secret to Rust over the existing sidecar stdout lifecycle channel, and a Rust client connects, authenticates, and completes one real Protobuf command/event round trip against the genuine spawned Python process — symmetric to how `native_runtime` authenticates to Python today (ADR-007), but with Python and Rust in the mirrored roles ADR-010 specifies.

## Acceptance criteria

The real `corytm` console script (not a throwaway proof script) gains a `serve` mode: it prints the existing `READY` lifecycle signal, opens a second `asyncio` loopback listener on its own port with a fresh random per-launch secret (independent of whatever port/secret it later uses to spawn/authenticate the Native Audio Runtime), and prints that port and secret as one further line over the same stdout channel. It then accepts exactly one client connection, requires the client to authenticate by sending the secret as the first frame, exchanges one `DesktopProofMessage` command/event round trip (Python replying with a distinct payload string proving the message was genuinely decoded and re-encoded by the real process, not echoed verbatim), and exits cleanly on the existing stdin `SHUTDOWN` signal. `corytm`'s existing no-argument behavior (`test_entrypoint.py`) is unchanged. A `cargo test` (mirroring `transport_proof.cpp`/`test_transport_proof.py`'s shape) spawns the real `corytm serve` process via `tauri-plugin-shell`, parses the port/secret line, connects as a TCP client, authenticates, sends a command, and asserts the returned event's content — proving the whole mechanism end to end. No native/C++ or `project.proto`/`proof.proto` code changes. Closed only once independently confirmed on a real, passing cross-platform (macOS + Windows) GitHub Actions run — this Feature introduces a genuinely new cross-platform surface (Rust as a raw TCP client authenticating against a real spawned Python server for the first time), so this project's established practice (RSK-002 through RSK-010) applies: no closing on local verification alone.

## Dependencies

FT-019 (done) — the Rust Protobuf codegen toolchain this Feature's round trip uses. ADR-010 (accepted) — the architecture this Feature makes real. ADR-007/FT-009 (done) — the transport pattern this Feature mirrors for the second, independent boundary.
