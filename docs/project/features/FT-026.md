# FT-026 — Wire Dorian's move_clip Tool to a Live Groq Model

Status: active
Epic: EP-013
Milestone: MS-002

## Objective

Implement EP-013's full scope: the provider-neutral `ModelProvider` boundary, the `GroqProvider` adapter, `corytm.dorian.agent`'s orchestration of `move_clip`'s existing tool/validation boundary, and the live evaluation harness proving GPT-OSS 20B does this reliably.

## Scope / Out of scope

In scope — see EP-013 for the full rationale; as implemented here:

- `src/backend/core/src/corytm/dorian/providers/base.py`: `ToolSpec`, `ToolCall`, the `ModelProvider` protocol, and `tool_spec_from_model` (builds a `ToolSpec` from an existing tool's own Pydantic proposal model).
- `src/backend/core/src/corytm/dorian/providers/groq.py`: `GroqProvider`, implementing `ModelProvider` against the official `groq` SDK's `AsyncGroq` client; the only module depending on `groq`'s types or response shape.
- `src/backend/core/src/corytm/dorian/agent.py`: `MOVE_CLIP_TOOL_SPEC` (built from `corytm.dorian.tools.MoveClipProposal`) and `propose_move_clip(instruction, provider)`, returning a validated `MoveClipProposal` or `None`.
- `src/backend/core/pyproject.toml`: adds `groq` as a runtime dependency; registers a `live_llm` pytest marker for the network-dependent evaluation.
- A live evaluation module, skipped automatically without a real `GROQ_API_KEY`, driving `propose_move_clip` against representative simple move-clip instructions.
- `docs/technical/architecture.md`: Model Routing and Human/Dorian Shared Application Path sections synchronized to reflect this first concrete provider wiring.

Out of scope: everything EP-013 names as out of scope (routing/registry, tier mapping, BYOK, other tools, Desktop UI, unconditional 120B upgrade).

## Acceptance criteria

- `tool_spec_from_model` produces a `ToolSpec` whose `parameters` matches `MoveClipProposal.model_json_schema()` exactly, covered by a colocated test.
- `GroqProvider.propose_tool_call` correctly translates a Groq-shaped tool-call response into a `ToolCall` (tool name, parsed JSON arguments), and returns `None` when the model makes no tool call — covered by tests against an injected fake client, no live network call.
- `propose_move_clip` returns a validated `MoveClipProposal` when a fake `ModelProvider` returns a valid `move_clip` call, returns `None` when the provider returns no call or a different tool name, and propagates `pydantic.ValidationError` when the provider's arguments fail `MoveClipProposal`'s own validation — covered by tests using a fake `ModelProvider`, no network.
- `make check-python` (pyright strict, ruff, pytest, all excluding `transport`) passes end to end with zero new warnings.
- A human, holding a real `GROQ_API_KEY`, runs the live evaluation and confirms GPT-OSS 20B reliably selects `move_clip` and produces valid arguments for representative simple instructions — or, if it does not meet the bar, confirms GPT-OSS 120B does, per ADR-013's documented fallback path.
