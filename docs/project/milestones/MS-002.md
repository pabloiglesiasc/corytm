# MS-002 — First Sound

Status: active

## Outcome

A user can create or open a Corytm project and produce actual sound through the full real stack via direct manual editing (user → desktop → Python core → Corytm Engine → Runtime → Native Audio Runtime → Tracktion Engine → sound), and Dorian can perform a real semantic edit through the same governed application path with an observable effect on that sound (user → Dorian → Corytm Engine → Runtime → sound) — Alpha's two end-to-end product paths (`docs/project/plan.md`), both real and demonstrable.

## Notes

Was `planned`, not `active`, until the two foundational architecture boundaries both product paths depend on were resolved: the desktop shell technology (ADR-006 — Tauri 2) and the Python↔C++ transport (ADR-007 — Protobuf over a local loopback-socket transport), both decided with explicit user approval under `CLAUDE.md` §5.
