# MS-002 — First Sound

Status: active

## Outcome

A user can create or open a Corytm project and produce actual sound through the full real stack via direct manual editing (user → desktop → Python core → Corytm Engine → Runtime → Native Audio Runtime → Tracktion Engine → sound), and Dorian can perform a real semantic edit through the same governed application path with an observable effect on that sound (user → Dorian → Corytm Engine → Runtime → sound) — Alpha's two end-to-end product paths (`docs/project/plan.md`), both real and demonstrable.

## Notes

Was `planned`, not `active`, until the two foundational architecture boundaries both product paths depend on were resolved: the desktop shell technology (ADR-006 — Tauri 2) and the Python↔C++ transport (ADR-007 — Protobuf over a local loopback-socket transport), both decided with explicit user approval under `CLAUDE.md` §5. EP-004, this Milestone's first Epic, is done (see `docs/project/status.md`): both ADRs are proven working in practice via minimal plumbing (Tauri shell, schema/codegen, transport, sidecar spawn/shutdown).

EP-005 (First Sound: Minimal Track and Clip Through Tracktion), this Milestone's second Epic, is `done`: a real Python entry point owning a minimal `Project`/`AudioTrack`/`AudioClip` crosses the ADR-007 transport, and the Native Audio Runtime genuinely materializes it as a real Tracktion `Edit` and renders real, deterministic, non-silent sound — offline, with no audio device, plus a real playable WAV file confirmed produced. Both required acceptance boundaries are satisfied: real Windows CI confirmation (independently verified from real job logs, not the user's report alone) and the human-only local audible smoke test EP-005's own scope called for as a distinct, non-automatable acceptance boundary. See `docs/project/epics/EP-005.md` and `docs/project/status.md` for the full evidence trail.

This Milestone's Outcome is still not fully reached even once EP-005 closes: EP-005 deliberately proves only a synthetic-fixture, one-track/one-clip slice driven by a hardcoded script, not a real user-facing project-creation flow, real imported audio, or Dorian's semantic-edit path.

**EP-006 (First Edit: Incremental Clip Move Through a Live Native Session)**, this Milestone's third Epic, is `done` (2026-09-02): both of this Outcome's still-unreached halves (manual Desktop editing, Dorian's semantic edit) depend on Corytm Engine expressing an edit as an incremental command rather than resending the whole project, which EP-005 deliberately left unproven (`docs/technical/architecture.md`'s "Engine Services and Incremental Updates" section named this direction without a concrete instance). EP-006 proved exactly one edit operation — moving a clip — end to end through three increments (Engine operation + wire schema, native live-session isolation, real transport wiring), each confirmed by real, independently-verified cross-platform CI evidence. See `docs/project/epics/EP-006.md` and `docs/project/status.md` for the full evidence trail.

This Milestone's Outcome is still not fully reached even once EP-006 closes: neither half — real Desktop project-creation/editing UI, nor Dorian's semantic-edit path — has been built yet; EP-006 only proved the shared command/live-session mechanism both future paths depend on.
