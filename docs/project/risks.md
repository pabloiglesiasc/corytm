Root cause, confirmed by reading protobuf `v36.1`'s `src/google/protobuf/port.h` and by a local standalone reproducer against libc++: `fixed_address_empty_string`'s actual type is chosen per-translation-unit via an SFINAE probe (`GlobalEmptyStringConstexpr::HasConstexprDefaultConstructor`) whose result depends on the active C++ standard — false under C++17, true under C++20, confirmed identically on libc++ too. `proof_schema` was compiled at `cxx_std_20` while `libprotobuf` is forced to `cxx_std_17` by protobuf's own `protobuf_configure_target`, so the two TUs disagreed on the symbol's type/mangled name.
