Before that next Epic, the user requested a focused Python architecture hardening iteration addressing two decisions discovered as real gaps while reviewing EP-005: canonical Corytm domain/application models were plain frozen `dataclasses`, and every `engine`/`runtime`/`generated` import only resolved because pytest's `pythonpath` ini option and Pyright's `extraPaths` each independently inserted `modules/`/`generated/` onto `sys.path` for their own tool run — real program execution had no equivalent, which is exactly why TK-014/EP-005's documented invocation was `PYTHONPATH=modules:generated uv run python main.py` run from inside `src/backend/core/`. Both were addressed as accepted ADRs rather than silent implementation choices, since both are exactly the kind of decision `decisions/README.md` says is worth recording: difficult to reverse once more Engine/Runtime/Dorian code exists, and likely to be silently violated by a future session without a durable rationale to point to.

**ADR-008** adopts Pydantic (v2) as the required modeling framework for canonical/domain/application data: `Project`/`AudioTrack`/`AudioClip` moved from frozen dataclasses to frozen (`ConfigDict(frozen=True)`) `BaseModel`s, with `AudioClip`'s existing invariants (`start_seconds` non-negative, `duration_seconds` strictly positive) expressed as `Field(ge=0)`/`Field(gt=0)` constraints instead of a hand-written `__post_init__` — no new invariant was invented for `AudioTrack`/`Project`, since none was implied by their existing dataclass behavior. `pydantic.ValidationError` subclasses `ValueError`, so the existing `pytest.raises(ValueError)` tests kept passing unchanged; new tests (`test_track.py`, `test_project.py`) prove nested/transitive validation specifically — constructing `AudioTrack`/`Project` from untrusted dict-shaped input (`model_validate`) with an invalid nested `AudioClip` is rejected, which the prior dataclasses never had to prove since they were only ever constructed from trusted in-process Python values. `pydantic`/`pydantic-core` ship prebuilt wheels for Python 3.14 on both macOS and Windows (checked against PyPI's actual release files before adopting, not assumed), so this adds no new build-toolchain requirement for either CI platform.

**ADR-009** makes `src/backend/core` a real, installable Python package rooted at `corytm` (`src/backend/core/src/corytm/`, a standard nested Python src-layout, built by `hatchling`; `[build-system]` was previously entirely absent, so `uv` had been treating this as a non-package "virtual" project). `engine`/`runtime` became `corytm.engine`/`corytm.runtime`; the Protobuf-generated bindings moved from a bare `generated/` to `corytm.generated`; the entry point became a `[project.scripts]` console script (`corytm = "corytm.main:main"`) instead of a bare `main.py`. Import rule adopted: absolute `corytm.`-qualified imports across the architecture's named ownership boundaries (Engine/Runtime/Native Audio Runtime/Dorian), relative imports permitted only between tightly-coupled sibling modules inside the same one of those subpackages (for example `engine/track.py` importing `.clip`) — applied consistently across every existing import in `src/backend/core`. The nested `src/corytm/` layout (rather than a flat `src/backend/core/corytm/`) was chosen deliberately: a flat layout would sit in the same directory the old cwd-based invocation already worked from, so the exact failure mode this migration fixes could keep silently passing undetected. Verified concretely, not just reasoned about: `uv run --project src/backend/core corytm`, invoked with `cwd` set to an unrelated `/tmp` directory (no `PYTHONPATH`, no prior `cd`), ran the real First Sound path end to end — real `native_runtime` process, real Tracktion Engine materialization/render, a genuine WAV file written into that unrelated directory. This is now a permanent automated test (`tests/test_entrypoint.py::test_entry_point_runs_independent_of_caller_working_directory`, `@pytest.mark.transport`, run via `check-transport`), not merely a one-off manual check — it invokes the real `uv run --project ... corytm` subprocess from a real different `cwd`, deliberately not a test that manipulates `sys.path` in a way production execution never would.
