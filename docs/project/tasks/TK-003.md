# TK-003 — Establish Frontend Development Foundation

Status: done
Feature: FT-002

## Objective

Establish a TypeScript-strict React project at `src/frontend/desktop/` with a working build, a passing test runner, and a passing linter, proving the frontend toolchain before any product UI exists.

## Scope / Out of scope

In scope: a Node/npm-managed project boundary at `src/frontend/desktop/` (`package.json`, `package-lock.json`); a minimal React + TypeScript project with `strict: true`; a build that succeeds; a test runner configured and passing against one minimal, non-domain test; a linter configured and passing; only the minimal non-domain component/artifact genuinely required to prove the toolchain works.

Out of scope: any product UI, screens, or Corytm-specific components; design-system or component-library selection; state-management choice; Storybook or equivalent; the desktop shell technology (Tauri or otherwise — remains unresolved); the unified root quality interface (FT-004); CI.

## Acceptance criteria

A Node/npm-managed React + TypeScript project exists at `src/frontend/desktop/` and builds successfully. TypeScript strict mode reports zero errors. A test runner is configured and discovers and passes the minimal non-domain test. A linter is configured and passes with no findings. No product UI or design-system implementation exists anywhere in the project.

## Dependencies

None.

## References

FT-002 (parent Feature — full accepted scope and exclusions); `docs/technical/architecture.md` (System Shape / Source Tree Direction — establishes `src/frontend/desktop/` as the frontend's home, and the Unresolved section — confirms the desktop shell technology is not decided here).

## Notes

Build tool, test runner, and linter are chosen during implementation as ordinary tooling decisions, not frozen here — the accepted direction is only "React/TypeScript... strict typing... build/test/lint tooling" (FT-002's Objective). Completion is verified using each tool's own native invocation directly, not a root Make command, since FT-004 doesn't exist yet.
