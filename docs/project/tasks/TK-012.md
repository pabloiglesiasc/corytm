# TK-012 — Implement the Corytm Engine Domain Model, Project Schema, and Runtime Projection

Status: done
Feature: FT-011
Milestone: MS-002

## Objective

Implement `Project`/`AudioTrack`/`AudioClip` under `src/backend/core/modules/engine/`, `src/schemas/project.proto`, its C++/Python codegen wiring, and a pure `modules/runtime/projection.py` that converts an Engine `Project` into a `MaterializeProjectCommand`; deduplicate the ADR-007 frame-read/write helpers out of `tests/test_transport_proof.py` into `modules/runtime/transport.py`.

## Scope / Out of scope

In scope: `modules/engine/clip.py` (`AudioClip`: id, start_seconds, duration_seconds), `modules/engine/track.py` (`AudioTrack`: id, clips), `modules/engine/project.py` (`Project`: id, tracks), each a minimal, strictly-typed Python type (dataclass or equivalent) with no behavior beyond construction/validation of its own fields; `src/schemas/project.proto` (`AudioClip`, `AudioTrack`, `Project`, `MaterializeProjectCommand`, `ProjectRenderedEvent`, each with an explicit `schema_version` field per ADR-002); `src/backend/audio/CMakeLists.txt` updated to generate and compile `project.pb.cc`/`.h` into a new `project_proto` static library (mirroring `proof_proto`'s `PUBLIC cxx_std_17` requirement exactly, per `.claude/memory/protobuf-generated-code-cxx-standard-abi.md` — this is required now, not merely precautionary, because FT-012's native code must link Tracktion Engine headers that need a newer C++ standard in the same executable, and only a strict compile-feature boundary between the protobuf-touching and Tracktion-touching translation units prevents TK-009's exact ABI bug from recurring); a small `project_schema.cpp` executable (mirroring FT-008's `proof_schema.cpp` exactly) that round-trips one of each new message type, registered as a ctest — proving the new codegen/link wiring in isolation before FT-012 builds the much larger Tracktion-integration executable on top of it; `Makefile`'s `check-python` target updated to also generate `project_pb2`; `modules/runtime/transport.py` (`read_frame`/`write_frame`/the transport magic constant, extracted from `tests/test_transport_proof.py`'s existing hand-rolled versions); `modules/runtime/projection.py` (`to_materialize_command(project: Project) -> MaterializeProjectCommand`, pure, no I/O); `pyproject.toml`'s `[tool.pyright] include` extended to `["tests", "modules"]` and `[tool.pytest.ini_options] testpaths` extended to `["tests", "modules"]`; unit tests colocated per `CLAUDE.md` §8 (`modules/engine/test_*.py`, `modules/runtime/test_*.py`); `tests/test_transport_proof.py` updated to import `read_frame`/`write_frame` from `modules/runtime/transport.py` instead of its own copy.

Out of scope: spawning the Native Audio Runtime process or sending anything over a real socket (FT-013); any native-side handling of `project.proto` beyond generating and linking its C++ bindings (FT-012); a real Python application entry point (FT-013); any field on `AudioClip`/`AudioTrack`/`Project` beyond what this slice's render proof needs (no name/color/mute/volume/frequency — frequency in particular is a Native Audio Runtime fixture-generation detail, not a domain concept, and does not appear in the schema).

## Acceptance criteria

`Project`/`AudioTrack`/`AudioClip` construct and round-trip through `to_materialize_command`, verified by unit tests colocated with each module. `project.proto` compiles via both `check-native`'s CMake codegen and `check-python`'s `uv`-driven codegen with no changes to `proof.proto`/FT-008's existing pipeline. `project_proto` (the new CMake library) sets `cxx_std_17` as a `PUBLIC` compile feature, matching `proof_proto` exactly. `project_schema` round-trips real values for every new message type and passes as a ctest. `tests/test_transport_proof.py` passes unchanged in behavior after switching to the shared `modules/runtime/transport.py` helpers (no duplication remains). `pyright` passes strict on `modules/` and `tests/`; `ruff check`/`ruff format --check` pass on the whole directory (already the case via `check-python`'s whole-directory invocation). `make check-python` and `make check-native` both pass locally end to end.
