# TK-017 — Implement Live-Edit Build/Move/Render and Its Isolation Proof

Status: done
Feature: FT-016
Milestone: MS-002

## Objective

Split `src/backend/audio/materializer.h`/`.cpp`'s existing `materialize()` into three reusable steps — build a live `Edit` from a `ProjectSpec`, apply a clip move to a live `Edit`, render a live `Edit` — and add `src/backend/audio/tests/live_session_proof.cpp`, a ctest proving a move applied to an already-built `Edit` is reflected in that same `Edit`'s next render.

## Scope / Out of scope

In scope: `materializer.h` gains `std::unique_ptr<tracktion::Edit> buildEdit (tracktion::Engine&, const ProjectSpec&)`, `bool moveClip (tracktion::Edit&, const std::string& trackId, const std::string& clipId, double newStartSeconds)`, and `RenderResult renderEdit (tracktion::Engine&, tracktion::Edit&, const std::string& projectId, const juce::File& outputDirectory)`; `materializer.cpp` implements them (`buildEdit` names the single `AudioTrack` and each `WaveAudioClip` after their `TrackSpec`/`ClipSpec` id via `insertWaveClip`'s existing `name` parameter, so `moveClip` can look them up by id via `Clip::getName()`/`AudioTrack::getName()`; `moveClip` calls `Clip::setStart (TimePosition::fromSeconds (newStartSeconds), /*preserveSync*/ false, /*keepLength*/ true)`, matching Corytm Engine's own `with_clip_moved` semantics of only touching start, never duration; `renderEdit` computes the render's end time by scanning the live `Edit`'s own current clip positions rather than trusting the original `ProjectSpec`, so it stays correct after a move) and `materialize()` becomes a thin composition of `buildEdit` + `renderEdit`, preserving its existing external behavior (including its existing empty-project/empty-clips early-return) exactly. A new `tests/headless_engine.h` factors out the headless deterministic-rendering `Engine`/`UIBehaviour`/`EngineBehaviour`/`PropertyStorage` stub set that `materializer_proof.cpp` already has and the new `live_session_proof.cpp` would otherwise duplicate a third time in `tests/` — the exact reuse trigger TK-013's own Notes named in advance; `materializer_proof.cpp` is refactored to use it (regression-guarded: it must keep passing unchanged), and `live_session_proof.cpp` uses it too. `tests/live_session_proof.cpp` builds one `Edit` (one track, one clip, e.g. 1s duration inside a window with room to move), renders it once as a baseline, calls `moveClip` to move the clip forward, re-renders the same `Edit`, and asserts the second render's sample-range content differs in the way a genuine move implies (near-silence before the new start, real signal after it) — plus asserts `moveClip` returns `false` and leaves the `Edit` unchanged for an unknown track/clip id. `CMakeLists.txt` gains the `live_session_proof` executable/ctest, linked against the existing `materializer` library.

Out of scope: `project.proto`/`wire_codec`/protobuf of any kind (this Feature is native-isolation only, mirroring FT-012 not needing `project.proto` until FT-013's equivalent); `native_runtime.cpp` (production, already-closed FT-010/FT-013 surface — not touched even though it has its own near-identical stub set, since extracting from it would be scope creep into separately-closed work; noted, not fixed, per `CLAUDE.md` §7); `toolchain_proof.cpp` (its `EngineBehaviour` doesn't override `getNumberOfCPUsToUseForAudio()`, so it isn't a true duplicate of the extracted stub set — left as is); any wire command/event, socket, or process spawning; any edit operation other than clip move; real-time/live playback.

## Acceptance criteria

`live_session_proof` builds and passes as a ctest: a baseline render of a freshly built `Edit` succeeds with the expected sample count/peak amplitude for its one clip; `moveClip` on that same `Edit` returns `true` and a second render of that same `Edit` object succeeds with a longer/shifted output whose sample content is near-silent up to the new start position and shows genuine signal after it; `moveClip` with a nonexistent track id or clip id returns `false` and a follow-up render of the untouched `Edit` still matches the original baseline exactly. `materializer_proof` continues to pass unchanged, proving `materialize()`'s external behavior (including its two-identical-calls determinism guarantee) survived the `buildEdit`/`renderEdit` refactor. `make check-native` passes locally end to end (all native targets, zero new warnings on the touched/added files) alongside the existing `toolchain_proof`/`proof_schema`/`project_schema`/`materializer_proof`/`native_runtime` targets.
