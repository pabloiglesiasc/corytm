# TK-020 — Prove Rust Protobuf Codegen for the Desktop-Facing Schema

Status: active
Feature: FT-019
Milestone: MS-002

## Objective

Give Tauri's Rust core (`src/frontend/desktop/src-tauri`) a working Protobuf codegen pipeline: a new, minimal Desktop-facing schema compiles into real Rust bindings via `prost`/`prost-build`, with `protoc` obtained by downloading and SHA256-verifying the same official, already-pinned release `src/backend/audio/CMakeLists.txt` uses — independent of whether `check-native` has already run. Prove the pipeline with a round-trip test, mirroring `proof_schema.cpp`/`test_schema.py`'s own role for the C++/Python side exactly.

## Scope / Out of scope

In scope:

- `src/schemas/desktop.proto`: one illustrative `DesktopProofMessage` (`schema_version: uint32`, `payload: string`), mirroring `proof.proto`'s own shape and role, package `corytm.schemas.desktop` — deliberately a distinct package/file from `project.proto`'s native-facing envelope (ADR-010).
- `src/frontend/desktop/src-tauri/build.rs`: a new `compile_desktop_proto()` step, added alongside the existing `tauri_build`/Windows-manifest logic (untouched). Fetches the platform-appropriate official `protoc` release (the same `v36.1` URLs/SHA256 hashes `src/backend/audio/CMakeLists.txt` already pins) into `OUT_DIR`, verifies the SHA256 before use, extracts the `protoc`/`protoc.exe` binary from the release zip, marks it executable on Unix, then runs `prost_build::Config::new().protoc_executable(...).compile_protos(...)` against `desktop.proto`.
- `src/frontend/desktop/src-tauri/Cargo.toml`: adds `prost` (runtime) and `prost-build`/`ureq`/`sha2`/`zip` (build-only) dependencies.
- `src/frontend/desktop/src-tauri/src/lib.rs`: `include!`s the generated bindings into a `desktop_proto` module, and a new `#[cfg(test)]` module constructing a `DesktopProofMessage`, encoding it, decoding it, and asserting equality.

Out of scope: any socket/transport code (Rust connecting to a running Python sidecar) — deferred to a later Feature under EP-009; any real UI-facing domain command; any Python-side change (the Python↔Native Audio Runtime schema/codegen/transport is untouched); any Desktop UI component or state-management choice.

## Acceptance criteria

- `cargo test` (from `src/frontend/desktop/src-tauri`) fails to compile before `desktop_proto`/`DesktopProofMessage` exist (confirming the test genuinely exercises new code, not something already satisfied).
- After implementation, `cargo test` passes: a `DesktopProofMessage` is constructed, encoded via `prost::Message::encode_to_vec`, decoded via `DesktopProofMessage::decode`, and the decoded value equals the original.
- The downloaded `protoc` archive's SHA256 is verified against the pinned hash before its contents are trusted; a mismatch fails the build loudly rather than silently proceeding.
- `make check-desktop` passes locally with the new toolchain wired in, with zero new compiler warnings.
- No file under `src/backend/audio/`, `src/backend/core/`, or `src/schemas/project.proto`/`proof.proto` is touched.
- Not closed `done` on local verification alone: per this project's established practice for a genuinely new cross-platform surface (a new Rust build-time network fetch + SHA256 check + zip extraction, untested on Windows from this session), a real, independently-verified passing Windows GitHub Actions run is required first.

## Notes

TDD: the `desktop_proto_tests` module in `lib.rs` is written first, referencing the not-yet-generated `desktop_proto::DesktopProofMessage`, confirmed failing to compile, then `desktop.proto`/`build.rs`/`Cargo.toml` are implemented to make it pass.

`ureq`+`sha2`+`zip` (build-only, minimal, widely-used crates with explicit SHA256 verification) were chosen over the third-party `protoc-prebuilt` helper crate after checking its actual behavior: it performs no cryptographic verification of the binary it downloads (only a `--version` string check) and is a low-commit-count, single-maintainer crate — a real step down from this project's established bar for this exact artifact (SHA256-pinned in CMake since TK-009/RSK-002). `protobuf-src` (compiles `protoc` from C++ source at Rust build time) was also considered and rejected: it would duplicate build effort the CMake side already pays for a working, verified binary. Both alternatives and the reasoning are recorded in ADR-010.

**Implemented and validated locally (2026-09-02):** TDD followed as planned — `desktop_proto_tests::desktop_proof_message_round_trips` was added first, referencing the not-yet-generated `desktop_proto::DesktopProofMessage`, and confirmed failing with a real compile error (`couldn't read .../out/corytm.schemas.desktop.rs`) before `desktop.proto`/`build.rs`/`Cargo.toml` were implemented.
