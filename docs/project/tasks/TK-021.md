# TK-021 — Wire and Prove the Desktop↔Python Socket Round Trip

Status: active
Feature: FT-020
Milestone: MS-002

## Objective

Give the real `corytm` entry point a `serve` mode implementing ADR-010's second listener/handshake, and prove Rust can connect to it, authenticate, and complete one real command/event round trip — the first time Rust acts as a raw socket client against a real spawned Python process.

## Scope / Out of scope

In scope:

- `src/schemas/desktop.proto`: unchanged (`DesktopProofMessage` already exists, TK-020).
- `Makefile`'s `check-python` codegen step: add `desktop.proto` to the `grpc_tools.protoc` invocation so Python gains `corytm.generated.desktop_pb2` bindings alongside the existing `proof`/`project` ones.
- `src/backend/core/src/corytm/runtime/desktop.py` (new): `serve_desktop_channel()` — prints `READY`, opens an `asyncio.start_server` listener on `127.0.0.1:0` with a fresh `secrets.token_hex(16)` secret, prints a `DESKTOP <port> <secret>` line, accepts one client connection, reads its first frame and requires it to equal the secret (raising if not), reads one frame as a `DesktopProofMessage` command, writes back a `DesktopProofMessage` event with a distinct payload proving genuine server-side handling, then reads stdin lines until `SHUTDOWN` and returns — reusing `corytm.runtime.transport.read_frame`/`write_frame` for framing, unchanged.
- `src/backend/core/src/corytm/main.py`: `main()` gains a `serve` branch (`sys.argv[1:] == ["serve"]` → `asyncio.run(serve_desktop_channel())`); the existing no-argument render-and-print behavior is otherwise untouched.
- `src/frontend/desktop/src-tauri/Cargo.toml`: adds the `net`/`io-util` features to the existing `tokio` dev-dependency (needed for a raw `TcpStream` client in the test).
- `src/frontend/desktop/src-tauri/src/lib.rs`: a new `#[cfg(test)]` module spawning `uv run --project ../../../backend/core corytm serve` via `tauri-plugin-shell`, parsing `READY` then the `DESKTOP <port> <secret>` line from its stdout, connecting a `tokio::net::TcpStream` to that port, writing the secret and one encoded `DesktopProofMessage` as length-prefixed frames matching `corytm.runtime.transport`'s exact wire format (a `u32` magic + `u32` length header, both little-endian, mirrored as local test-only helper functions — not a new production module, matching how `transport_proof.cpp`/`test_transport_proof.py` first proved this same framing on the Python↔native boundary before any reusable helper existed there), reading back one frame, decoding it as `DesktopProofMessage`, and asserting its content; then writing `SHUTDOWN\n` to the child's stdin and asserting a clean exit, mirroring `sidecar_shuts_down_via_explicit_protocol`'s teardown exactly.

Out of scope: any real UI-facing domain command or envelope beyond `DesktopProofMessage`; any Rust production (non-test) code that spawns or talks to the sidecar (`lib.rs`'s `run()` still only starts the Tauri app; no real sidecar wiring into the shipped app yet); any Desktop UI/state-management/rendering choice; any change to `project.proto`, `proof.proto`, or any file under `src/backend/audio/` or `src/backend/core`'s Python↔native path.

## Acceptance criteria

- The new `cargo test` fails to compile or run before `corytm serve` and `desktop.py` exist (confirming it genuinely exercises new code).
- After implementation: `cargo test` passes, completing a real round trip — Rust receives a `DesktopProofMessage` event whose payload differs from what it sent (proving real server-side decode/re-encode, not an echo) and whose `schema_version` matches the command's.
- `corytm serve` authenticates the connection (rejects/closes on a wrong secret) before accepting any command frame.
- `uv run --project src/backend/core corytm` with no arguments still renders the existing first-sound fixture unchanged (`test_entrypoint.py` passes unmodified).
- `make check-desktop` and `make check-python` both pass locally with zero new compiler/type/lint warnings.
- No file under `src/backend/audio/` or `src/schemas/project.proto`/`proof.proto` is touched.
- Not closed `done` on local verification alone: per this project's established practice (RSK-002 through RSK-010), a real, independently-verified passing Windows GitHub Actions run is required first — this is a genuinely new cross-platform surface (Rust as a raw TCP client authenticating against a real Python server).
