# TK-024 — Desktop UI Trigger for the Move-Clip Command

Status: done
Feature: FT-022
Milestone: MS-002

## Objective

Give the real Tauri app a minimal UI control that invokes TK-023's now-proven move-clip command and displays its result — the first real UI-facing domain action a human can trigger from an actual Corytm Desktop window.

## Scope / Out of scope

In scope:

- `src/frontend/desktop/src-tauri/build.rs`: `tauri_build::Attributes` gains `.app_manifest(tauri_build::AppManifest::new().commands(&["move_clip"]))`, auto-generating the command's permission file.
- `src/frontend/desktop/src-tauri/src/lib.rs`: a production `#[tauri::command] async fn move_clip(...)` using TK-023's shared `write_frame`/`read_frame` functions to connect to the Desktop channel (port/secret captured in Tauri-managed state right after `spawn_desktop_sidecar` succeeds, mirroring how the `CommandChild` is already captured), send one hardcoded `MoveClipCommand` matching `desktop.py`'s fixture project exactly, and return the resulting `ClipMovedEvent`'s fields to the frontend; registered via `.invoke_handler(tauri::generate_handler![move_clip])`.
- `src/frontend/desktop/src-tauri/capabilities/default.json`: `"allow-move-clip"` added to `permissions`.
- `src/frontend/desktop/package.json`: `@tauri-apps/api` added (needed for the frontend to call `invoke`).
- `src/frontend/desktop/src/App.tsx`: one button that calls `invoke('move_clip')` and displays the result (or error) — disabled after the first click/result, since the Desktop channel server behind it supports exactly one round trip per app session (FT-022's own Out of scope).

Out of scope: any command/event schema change (TK-023's own scope); any visual/UX design investment beyond function; multiple concurrent triggers, retries, or reconnection; real project creation/persistence/authoring UI.

## Acceptance criteria

- `cargo test` continues to pass; the new `move_clip` command is proven to call the exact same `write_frame`/`read_frame`/connect logic as any test exercising it, by reading the code, not merely by a test passing (a shared-function claim a test alone cannot fully prove) — mirroring TK-022's own precedent for `spawn_desktop_sidecar`.
- `make check-desktop` and a full clean `make check` pass locally with zero new compiler warnings.
- Human-verified, as a distinct non-automatable acceptance boundary (mirroring TK-022's own precedent): running `npm run tauri dev`, clicking the button, and observing the real moved-clip result (a genuinely different start time than the fixture's original) rendered in the actual window.

Under the current Feature-level delivery model (`CLAUDE.md` §6/§7), this Task's own Done is local validation plus the human confirmation above — it does not individually wait on its own Windows CI run. `RSK-014` (Tauri's app-command ACL system and a frontend-triggered round trip, both exercised on Windows for the first time) is a real, still-open risk, but the required Windows GitHub Actions confirmation is tracked once, at FT-022's own `validating` stage, across this Task and TK-023 together.

## Dependencies
