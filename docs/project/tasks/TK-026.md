# TK-026 — Desktop Channel Create/Open/Save Commands

Status: done
Feature: FT-023
Milestone: MS-002

## Objective

Extend `project.proto`'s `Command`/`Event` oneof with `CreateProjectCommand`/`SaveProjectCommand`/`OpenProjectCommand` and their events, restructure `serve_desktop_channel()` into a multi-command per-connection session backed by TK-025's persistence module, and update the Desktop channel's one existing real caller (`lib.rs`'s `move_clip`) to the resulting enveloped wire format.

## Scope / Out of scope

In scope:

- `src/schemas/project.proto`: `CreateProjectCommand { uint32 schema_version = 1; }` / `ProjectCreatedEvent { uint32 schema_version = 1; string project_id = 2; }`; `SaveProjectCommand { uint32 schema_version = 1; string file_path = 2; }` / `ProjectSavedEvent { uint32 schema_version = 1; string project_id = 2; string file_path = 3; }`; `OpenProjectCommand { uint32 schema_version = 1; string file_path = 2; }` / `ProjectOpenedEvent { uint32 schema_version = 1; string project_id = 2; string file_path = 3; uint32 track_count = 4; uint64 rendered_sample_count = 5; double peak_amplitude = 6; }`; all three command/event pairs added to `Command`/`Event`'s existing oneofs alongside `materialize`/`move_clip`.
- `src/backend/core/src/corytm/runtime/desktop.py`: `serve_desktop_channel()` restructured to read a `Command`-enveloped frame in a loop (ending cleanly on the client closing the connection — `asyncio.IncompleteReadError`/EOF from `read_frame`, not an error condition), dispatching on `WhichOneof("command")` against one in-memory "current project" slot seeded with the existing hardcoded fixture (so `MoveClipCommand`'s existing observable behavior is unchanged): `create_project` replaces the slot with a fresh empty `Project` (a new id, zero tracks) and replies `ProjectCreatedEvent`; `save_project` calls `persistence.save_project` against the current slot and replies `ProjectSavedEvent`, raising `ValueError` if nothing is loaded/created yet; `open_project` calls `persistence.load_project`, replaces the slot, re-materializes the loaded project via the existing `materialize_project` (a fresh temp output directory), and replies `ProjectOpenedEvent` carrying its track count and the real render evidence; `move_clip` behaves exactly as today, via `move_clip_in_session` against the current slot.
- `src/frontend/desktop/src-tauri/src/lib.rs`: `move_clip` and its `desktop_channel_tests` sends a `project_proto::Command { command: Some(project_proto::command::Command::MoveClip(...)) }` instead of a bare `MoveClipCommand`, and decodes `project_proto::Event`, matching on `event: Some(project_proto::event::Event::ClipMoved(...))`; `MoveClipResult`'s fields and the JSON shape returned to the frontend are unchanged.

Out of scope: any native file dialog, new `#[tauri::command]`, or UI control; `project.proto`'s existing `MaterializeProjectCommand`/`ProjectRenderedEvent`/`MoveClipCommand`/`ClipMovedEvent` fields (only the oneofs gain new members); any change to `native_runtime.cpp`/`wire_codec`/anything under `src/backend/audio/`.

## Acceptance criteria

- A new automated Python test (`src/backend/core/tests/test_desktop_channel_session.py` or extending the existing `tests/test_desktop_channel.py`) drives the real `corytm serve` sidecar over one connection: `CreateProjectCommand` → `ProjectCreatedEvent`; `SaveProjectCommand` (a real temp path) → `ProjectSavedEvent`, file confirmed round-tripping via `persistence.load_project` directly; `OpenProjectCommand` (a distinct, separately-written fixture file with a known track/clip) → `ProjectOpenedEvent` with the correct `track_count` and non-zero `rendered_sample_count`/`peak_amplitude`; `MoveClipCommand` (enveloped) → `ClipMovedEvent` matching today's existing fixture behavior exactly; connection close ends the server task cleanly with no hang.
- `SaveProjectCommand` sent before any `CreateProjectCommand`/`OpenProjectCommand` in the same connection still succeeds, since the slot is seeded with the existing fixture (no regression to a connection that only ever sends `MoveClipCommand`, exactly like today).
- The updated `desktop_channel_tests::move_clip_command_moves_the_fixture_clip_and_renders_the_effect` (or equivalent) passes against the enveloped wire format with the same assertions as before.
- `make check-python`, `make check-native`, `make check-transport` pass; `cargo build`/`cargo test` under `src-tauri` pass with zero new warnings; a full local `make check` passes end to end.

## Notes

TDD throughout: the new/updated Python and Rust tests are written and confirmed failing (wrong message type, or the not-yet-existing command handlers) before the corresponding implementation lands.

**Implemented and validated locally (2026-09-02):** `runtime/desktop.py`'s `serve_desktop_channel()` now delegates its one connection to a new `_run_session` loop, which reads a `Command`-enveloped frame, dispatches it via a new `_dispatch_command`, writes back the resulting `Event`, and repeats until the client disconnects (`asyncio.IncompleteReadError` from `read_frame`, caught to end the loop cleanly — no error, no hang). `_dispatch_command` handles `create_project` (a fresh `Project(id=uuid4(), tracks=())`), `save_project`/`open_project` (via TK-025's `persistence` module, with Open re-materializing through the existing `materialize_project`), and `move_clip` (unchanged, via the existing `move_clip_in_session`). During Review, the originally-planned `current_project is None` guard clauses for `save_project`/`move_clip` were found to be dead code — `_run_session` always seeds the slot with the existing hardcoded fixture before the loop starts, so `current_project` is never `None` when dispatched — and were removed along with the now-unneeded `Project | None` typing, simplifying `_dispatch_command`'s signature to a plain `Project`.

Three new automated tests in `tests/test_desktop_channel_session.py` drive the real `corytm serve` sidecar over one connection: `test_create_and_save_project_over_one_connection` (not transport-marked — no native process needed) proves create→save, with the saved file independently confirmed round-tripping via `persistence.load_project`; `test_open_project_re_materializes_it_and_move_clip_still_applies` (transport-marked) proves a separately-prepared fixture file opens correctly (`track_count`, real `rendered_sample_count`/`peak_amplitude` from a genuine native materialize) and that a subsequent `MoveClipCommand` still applies; `test_move_clip_still_works_without_any_prior_command` (transport-marked) proves the pre-existing move-clip behavior is byte-for-byte unchanged when nothing else runs first. All three drive `serve_desktop_channel()` as an in-process `asyncio` task (mirroring `tests/test_desktop_channel.py`'s existing pattern) and needed one addition to that pattern: a `_FakeStdin` class yielding one `SHUTDOWN` line, so the test can let the server run through its full lifecycle — including the post-session stdin wait — without hitting pytest's own stdin capture (which raises on read). The pre-existing `tests/test_desktop_channel.py` test was updated to send its `MoveClipCommand` wrapped in `Command`, matching the new wire format; its assertion (an unknown clip id fails the session) is otherwise unchanged.

On the Rust side, `lib.rs`'s `move_clip` now sends `project_proto::Command { command: Some(command::Command::MoveClip(...)) }` and decodes `project_proto::Event`, matching on `event::Event::ClipMoved(...)` (returning an error string if a different event variant were ever received) — `MoveClipResult`'s JSON shape to the frontend is unchanged. Its doc comment was corrected: it previously said the channel "serves exactly one command per app session," which is no longer true (only the one-connection-per-session limit is unchanged).

Validated beyond this Task's own minimum, matching this project's established practice: `make check-python` (38 passed, pyright 0 errors, ruff clean), `make check-native` (`ctest` 5/5, unaffected — the additive `project.proto` messages introduced no new warnings), `cargo build --lib` and `cargo build --release --bin app` both clean with zero warnings, `cargo test` (all 3 Rust tests, including the updated `move_clip_command_moves_the_fixture_clip_and_renders_the_effect`), `make check-transport` (10 passed, including this Task's two transport-marked tests), and a full clean `make check` (all five targets, including `make check-desktop`'s release build/`.app`/`.dmg` bundling) passing end to end. `git status` confirmed only this Task's own named files changed.
