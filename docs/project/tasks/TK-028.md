# TK-028 — Minimal Create/Open/Save UI

Status: done
Feature: FT-024
Milestone: MS-002

## Objective

A minimal, function-only Desktop UI triggering TK-027's `create_project`/`save_project`/`open_project` commands through real native OS dialogs, plus the human confirmation step EP-011's own acceptance criteria requires for behavior that can't be exercised headlessly.

## Scope / Out of scope

In scope:

- `App.tsx`: a "New Project" button calling `invoke('create_project')`; a "Save" button calling `@tauri-apps/plugin-dialog`'s `save()` to resolve a real path, then `invoke('save_project', { filePath })`; an "Open" button calling `open()` (single file, not directory) then `invoke('open_project', { filePath })`; each result/error displayed the same plain way the existing `move_clip` trigger already does (`JSON.stringify` in a `<pre>`, an error `<p>`) — no new visual design investment, per FT-024's own Out-of-scope.
- Human confirmation, performed by the user directly (not this session): `npm run tauri dev`, click New Project, click Save and choose a real path in the real native dialog, quit the app, relaunch, click Open and choose that same file in the real native dialog, and confirm the displayed result shows the expected track/render data.

Out of scope: any styling/design-system investment; any other UI control; automated end-to-end testing of the real native dialog itself (not headlessly exercisable — covered by the human confirmation step instead).

## Acceptance criteria

- `tsc -b`, `vite build`, `oxlint`, and `vitest run` all pass on the changed frontend files.
- The human confirmation step above is performed and its real result (not a mocked one) is recorded in this Task's Notes before this Task, FT-024, and EP-011 can close.

## Dependencies

TK-027 (the commands this Task's UI triggers).

## References

`src/frontend/desktop/src/App.tsx`'s existing `move_clip` button (the pattern this Task extends); `@tauri-apps/plugin-dialog`'s JS API (`save()`/`open()`, confirmed via its official docs in TK-027).
