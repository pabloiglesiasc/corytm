# TK-029 — Engine Authoring Operations and Desktop Channel Add-Track/Add-Clip Commands

Status: done
Feature: FT-025
Milestone: MS-002

## Objective

Implement the Engine-level "add a track" / "append a clip" operations and wire them through `project.proto` and the Desktop channel's dispatch, proven entirely by automated Python tests — no Rust or UI change (TK-030).

## Scope / Out of scope

In scope:

- `AudioTrack.with_clip_appended(*, clip_id: str, duration_seconds: float) -> AudioTrack` (`track.py`): computes the new clip's `start_seconds` as `0.0` if the track has no clips, else `max(clip.start_seconds + clip.duration_seconds for clip in self.clips)` — non-overlapping placement by construction, no caller-supplied position.
- `Project.with_track_added(*, track_id: str) -> Project` (`project.py`): appends an empty `AudioTrack`.
- `Project.with_clip_appended(*, track_id: str, clip_id: str, duration_seconds: float) -> Project` (`project.py`): finds the named track, delegates to its `with_clip_appended`, raises `ValueError` if `track_id` doesn't exist — mirroring `with_clip_moved`'s exact shape.
- `src/schemas/project.proto`: `AddAudioTrackCommand { schema_version }`; `AudioTrackAddedEvent { schema_version, project_id, track_id, track_count }`; `AddAudioClipCommand { schema_version, track_id, duration_seconds }`; `AudioClipAddedEvent { schema_version, project_id, track_id, clip_id, start_seconds, duration_seconds, rendered_file_path, rendered_sample_count, peak_amplitude }` — added to `Command`/`Event`'s oneofs as fields 6/7.
- `src/backend/core/src/corytm/runtime/session.py`: `add_clip_in_session(project, *, track_id, clip_id, duration_seconds, output_directory) -> tuple[Project, AudioClip, ProjectRenderedEvent]`.
- `src/backend/core/src/corytm/runtime/desktop.py`: `_dispatch_command` gains `add_track`/`add_clip` branches, generating server-side `uuid4` ids exactly as `create_project` already does for `project_id`.
- Colocated Engine tests (`test_track.py`, `test_project.py`) and a new automated `tests/test_desktop_channel_session.py` case driving the real channel end to end.

Out of scope: any Rust/`lib.rs` or frontend change (TK-030); any native/`native_runtime.cpp`/`materializer.cpp`/`wire_codec` change (none is needed — `toProjectSpec` already converts every track/clip generically; only `buildEdit`'s existing `tracks[0]`-only limitation is left unchanged, per EP-012's Out of scope).

## Acceptance criteria

- `test_track.py`: appending to an empty track places the clip at `start_seconds=0.0`; appending to a track with existing clips places it immediately after the last one ends; the original track is unchanged (immutability).
- `test_project.py`: `with_track_added` appends an empty track without disturbing existing ones; `with_clip_appended` delegates correctly and raises `ValueError` (matching `"track"`) for an unknown `track_id`.
- A new `tests/test_desktop_channel_session.py` test drives the real Desktop channel over one connection: `CreateProjectCommand` → `AddAudioTrackCommand` (`track_count == 1`) → `AddAudioClipCommand` twice (the second clip's `start_seconds` equals the first clip's `start_seconds + duration_seconds`, proving non-overlapping append) → each `AudioClipAddedEvent` carries genuine non-zero `rendered_sample_count`/`peak_amplitude`.
- `make check-python` and `make check-transport` pass; `pyright` strict and `ruff` clean.

## Notes

**Implemented and validated (2026-09-02):** `AudioTrack.with_clip_appended` computes the new clip's start as `0.0` (empty track) or `max(clip.start_seconds + clip.duration_seconds for clip in self.clips)` (non-empty); `Project.with_track_added`/`with_clip_appended` mirror `with_clip_moved`'s exact find/delegate/raise-on-unknown-id shape. `project.proto` gained `AddAudioTrackCommand`/`AudioTrackAddedEvent`/`AddAudioClipCommand`/`AudioClipAddedEvent` as oneof fields 6/7 — neither new command carries a `project_id` input (unlike `MoveClipCommand`'s existing, already-vestigial one): the session already scopes to one current project, and neither Rust nor the frontend has a real value to put there; both events still echo `project_id`, matching the other events' convention. `session.add_clip_in_session` mirrors `move_clip_in_session`'s "mutate, then materialize" shape, but simpler — a newly authored clip has no live-session incremental counterpart, so the whole mutated project is re-sent via the already-proven `materialize_project`, exactly as `open_project` already does. `desktop.py`'s `_dispatch_command` gained `add_track` (pure mutation, no render, mirroring `create_project`) and `add_clip` (mutation + full re-render, mirroring `move_clip`'s report shape) branches, both generating server-side `uuid4` ids exactly as `create_project` already does.

No native/C++ change was needed: confirmed by reading `wire_codec.cpp`'s `toProjectSpec` (already converts every track/clip generically) before starting, not assumed.
