# TK-031 — Provider-Neutral Model-Provider Boundary and Groq Adapter

Status: done
Feature: FT-026

## Objective

Build `corytm.dorian.providers`: the provider-neutral `ToolSpec`/`ToolCall`/`ModelProvider` boundary, and `GroqProvider`, its first (and Alpha's only) concrete implementation, against the official `groq` SDK.

## Scope / Out of scope

In scope: `providers/base.py` (`ToolSpec`, `ToolCall`, `ModelProvider` Protocol, `tool_spec_from_model`), `providers/groq.py` (`GroqProvider`), `pyproject.toml`'s new `groq` runtime dependency, and colocated tests for both — using an injected fake client for `GroqProvider`, no live network call.

Out of scope: anything that calls `move_clip`'s own schema or orchestrates a full propose-then-validate flow (TK-032); the live evaluation (TK-032).

## Acceptance criteria

- `tool_spec_from_model(name=..., description=..., model_cls=...)` returns a `ToolSpec` whose `parameters` equals `model_cls.model_json_schema()`.
- `GroqProvider.propose_tool_call` sends `instruction` as a user message and the given `tools` translated into Groq's OpenAI-compatible `tools` shape, and:
  - returns a `ToolCall(tool_name=..., arguments=...)` decoded from a tool-call response (arguments parsed from the response's JSON string), proven against an injected fake client;
  - returns `None` when the response carries no tool call, proven the same way.
- `pyright` (strict) and `ruff check`/`ruff format --check` pass on the new modules with zero suppressions.
- `uv run pytest -m "not transport"` passes, including the new tests, with no live network call made.

## References

`decisions/ADR-013.md` — the protected decision this Task implements. `src/backend/core/src/corytm/dorian/tools.py` — the existing `MoveClipProposal` this boundary is designed to build a `ToolSpec` from (consumed by TK-032, not this Task).
