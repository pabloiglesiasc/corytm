# TK-035 — Python Test Layout Migration

Status: done
Feature: FT-028

## Objective

Structurally separate Corytm's Python production and test trees, per the user's explicit override of the testing-architecture review's own recommendation: migrate every test currently colocated under `src/corytm/**` into `src/backend/core/tests/{engine,dorian,runtime}/`, and relocate the tests already under `src/backend/core/tests/` into `src/backend/core/tests/integration/` — inspecting each file's actual content individually rather than classifying mechanically by filename — while preserving every import, discovery, marker, and behavioral guarantee unchanged.

## Scope / Out of scope

In scope: every `test_*.py` file under `src/backend/core/src/corytm/**` and `src/backend/core/tests/**`; `pyproject.toml`'s `testpaths` and Ruff per-file-ignore globs; `docs/technical/architecture.md`'s Structural Evolution "Tests" bullet (now synchronized — see this Task's Notes).

Out of scope: any production code change; any test's assertions or behavior; a Hatchling packaging exclude (only warranted if a concrete, independent packaging reason remains after the migration — none was found, since no test file will remain under `src/corytm/**` at all).

## Acceptance criteria

- Every file inspected individually; classification recorded in this Task's Notes with the reasoning per file, not inferred from filename alone.
- `src/backend/core/tests/engine/{test_clip,test_track,test_project,test_persistence}.py`, `src/backend/core/tests/dorian/{test_tools,test_agent}.py`, `src/backend/core/tests/dorian/providers/{test_base,test_groq}.py`, `src/backend/core/tests/runtime/{test_transport,test_projection}.py` exist, each with any relative import rewritten to an absolute `corytm.`-qualified one.
- `src/backend/core/tests/integration/` contains every file previously flat under `src/backend/core/tests/`, content unchanged.
- No file remains under `src/corytm/**` matching `test_*.py`.
- `pyproject.toml`'s `testpaths` no longer names `src/corytm`; Ruff's per-file-ignore glob for test files covers the new nested paths (no longer `tests/*`, which only matches one level deep) and the now-dead `src/corytm/**/test_*.py` entry is removed.
- `pytest -m "not transport and not live_llm"`, `pytest -m transport`, `pyright`, `ruff check`, `ruff format --check` all pass with the same pass/skip/deselect counts as the pre-migration baseline (57 passed/16 deselected; 14 passed/59 deselected for transport).

## Notes

### Per-file classification (individually inspected, not inferred from filename)

**`tests/engine/`** — each imports and exercises only `corytm.engine.*`: `test_clip.py` (`AudioClip` construction/validation only), `test_track.py` (`AudioTrack`+`AudioClip`), `test_project.py` (`Project`+`AudioTrack`+`AudioClip`), `test_persistence.py` (`engine.persistence.save_project`/`load_project` round-tripping `engine` models — persistence is Engine's own ownership area, not a separate subsystem). All four used relative imports (`from .clip import ...`), confirming they were genuinely package-internal tests, not merely colocated by convenience — each rewritten to `corytm.engine.<module>`.

**`tests/runtime/`** — `test_transport.py` exercises only `runtime.transport`'s frame read/write helpers (relative import rewritten). `test_projection.py` exercises `runtime.projection`'s `to_materialize_command`/`to_move_clip_command`; it imports `corytm.engine.*` only to build fixture input, not to test Engine's own behavior — the responsibility under test (projecting Engine state into wire messages) belongs entirely to Runtime, so this stays a Runtime-exclusive unit test, not integration. Its one relative import (`from .projection import ...`) rewritten; its two already-absolute `corytm.engine.*` imports merged into one sorted block per Ruff's import ordering.

**`tests/dorian/`** — `test_tools.py` (validates `MoveClipProposal` alone) and `test_agent.py` (`propose_move_clip` against an injected `_FakeProvider`, never a real network call) both already used absolute imports and touch nothing outside `corytm.dorian`. `test_agent_live_eval.py` — not originally enumerated in the review's own classification pass (it was discussed only as a marker/exclusion concern), but is unambiguously a Dorian-exclusive test by the same rule (`propose_move_clip` against a real `GroqProvider`, no Engine/Runtime/native involvement) — moved here too, `live_llm` marker and `skipif(GROQ_API_KEY)` guard untouched, already-absolute imports needed no change.

**`tests/dorian/providers/`** — `test_base.py` (`ToolSpec`/`ToolCall`/`tool_spec_from_model`, no external dependency) and `test_groq.py` (`GroqProvider` against a fully mocked `AsyncGroq` client via `AsyncMock`, no real network call) both test only `corytm.dorian.providers`; nested under `dorian/` rather than flattened, mirroring the source package's own `dorian/providers/` sub-boundary (CTO/AI & Sound's own internal ownership split) rather than the Feature's illustrative sketch verbatim — a refinement, not a deviation, since providers/ is genuinely dorian's own tests, just organized to mirror the one real internal boundary that already exists in the source tree.

**`tests/integration/`** — every file already living under the old flat `tests/` moved here unchanged in content, each confirmed to genuinely cross a boundary: `test_desktop_channel.py`/`test_desktop_channel_session.py` (Runtime's `desktop`+`transport`+Engine, several also spawning a real `native_runtime` process); `test_dorian_move_clip.py` (Dorian+Engine+a real native render); `test_entrypoint.py`/`test_first_sound.py`/`test_incremental_edit.py`/`test_move_clip_in_session.py`/`test_transport_proof.py` (real subprocess/native-process round trips); `test_proof_schema.py` and `test_environment.py` (protobuf-codegen/interpreter-version toolchain proofs belonging to no single subsystem — the "doesn't own one subsystem" case `integration/` also covers, not literal boundary-crossing, the nearest fit of the four available buckets).

### Verification (real execution, not inspection alone)

Moving `tests/test_entrypoint.py` and `tests/test_transport_proof.py` one directory deeper broke a real, concrete thing a mechanical `git mv` would have missed: both computed the native build directory / `uv --project` directory via a hardcoded `Path(__file__).resolve().parents[N]` count. First `pytest -m transport` run after the move failed exactly one test (`test_transport_proof.py`) with the derived path off by one directory (`.../backend/backend/audio/build`, confirming the depth mismatch); `test_entrypoint.py`'s analogous `parents[1]` had the identical latent bug (not yet triggered because it still happened to resolve to an existing directory one level differently, but wrong all the same — checked directly, not assumed safe just because it passed). Both `parents[N]` counts incremented by exactly one; `pytest -m transport` re-run clean afterward: `14 passed, 59 deselected`, matching the pre-migration baseline exactly.

Full validation, run through the real `make` targets (not just direct `uv run` calls): `make check-python` → `57 passed, 16 deselected`, `pyright` 0 errors, `ruff check`/`ruff format --check` clean (40 files); `make check-transport` → `14 passed, 59 deselected`. All four counts match the pre-migration baseline exactly. `find src/corytm -name "test_*.py"` returns nothing — no test file remains inside the installed package tree, so the packaging-hygiene concern the original review flagged (test code shipping inside the production wheel) is resolved by construction; no Hatchling exclude was needed or added. `docs/technical/architecture.md`'s Structural Evolution "Tests" bullet was rewritten to describe the new mirrored-tree convention (the Native Audio Runtime's own, separate production-root/`tests/` split is explicitly called out as unaffected).
