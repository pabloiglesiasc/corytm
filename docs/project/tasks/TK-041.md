# TK-041 — Desktop-Channel Play/Stop Rust Commands and ACL

Status: done
Feature: FT-030

## Objective

Add `play`/`stop`/`get_playback_position` `#[tauri::command]`s on the existing held `DesktopConnection`, registered in the invoke handler and `capabilities/default.json`, reachable through the real IPC/ACL pipeline.

## Scope / Out of scope

`src/frontend/desktop/src-tauri/src/lib.rs` and `capabilities/default.json` only. No frontend UI change (TK-042).

## Acceptance criteria

- `play`/`stop`/`get_playback_position` Rust commands, matching the existing zero-argument shape (`create_project`/`add_track`), reach through `send_command` and decode their expected event variant.
- Registered in `generate_handler!` (both `run()` and the ACL test's own real-context build) and granted in `capabilities/default.json`.
- A `cargo test` drives Play → GetPlaybackPosition → Stop over one held connection (mirroring `create_add_track_add_clip_all_succeed_over_one_held_connection`'s shape), tolerating a no-device environment the same way the Python integration test does.
- `real_app_commands_are_permitted_and_readiness_is_observable` extended to confirm `play` is permitted by the real compiled-in ACL.
- `cargo test` and `cargo build --release --bin app` pass with zero new warnings.

## Notes

`build.rs`'s `AppManifest::new().commands(&[...])` list — not automatic `#[tauri::command]` detection — is what drives `permissions/autogenerated/*.toml` generation; a first `cargo build --lib` after adding `play`/`stop`/`get_playback_position` failed at build-script time (`Permission allow-play not found`) until the three names were added there too. `PlayCommand`'s `project` field is deliberately left `None` at this Desktop-channel hop: `desktop.py`'s `play` dispatch branch (TK-040) never reads it, always using its own server-tracked `current_project` — the same "shared message, field meaningful on one hop only" precedent `MoveClipCommand.project_id` already established (FT-025's own notes call it "vestigial" at this hop).

### Validate

`cargo test` (8 passed, including the new `play_reports_advancing_position_and_stop_halts_it` and the extended ACL test) and `npm run tauri build` (full release bundle + DMG) both pass with zero new warnings. The new test ran against a real local audio device: `device_opened: true`, position genuinely advanced across two polls 300ms apart.
