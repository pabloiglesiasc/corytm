# TK-042 — Desktop UI: Play/Stop Control and Live Playhead

Status: done
Feature: FT-030

## Objective

Give the real Corytm Desktop app a Play/Stop control and a live playhead display, reusing the existing card-layout/design-token scaffold, polling `get_playback_position` while playing.

## Scope / Out of scope

`src/frontend/desktop/src/App.tsx` only. No Rust or Python change (TK-039/TK-040/TK-041).

## Acceptance criteria

- A new "Playback" card, matching the existing "Project"/"Track & Clip" cards' structure exactly, with Play (enabled once a clip exists and nothing is currently playing) and Stop (enabled only while playing) buttons.
- A live position readout, polling `get_playback_position` every 200ms while playing, stopping automatically when the backend reports `is_playing: false` or on a poll failure.
- The `ui-ux-review` skill applied against `docs/product/design.md`, findings addressed before Close.
- `npm run build`, `npm run test`, `npm run lint` all pass.

## Notes

`hasClip` is derived, not directly reported by any single event: set `true` on a successful Add Clip, and from `open_project`'s `rendered_sample_count > 0` (a project with clips renders non-silent output; one with none doesn't) — `track_count` alone can't distinguish an empty track from one with clips. `controlsDisabled` (`pending || !channelReady || playing`) now also covers `playing`, so every other control (New/Save/Open/Move/Add Track/Add Clip) is disabled while playing, avoiding project mutation mid-playback; Stop deliberately uses its own, narrower disabled condition (`pending || !channelReady || !playing`) since it must stay enabled precisely when the shared flag would otherwise disable it.

### Review (`ui-ux-review` against `docs/product/design.md`)

Reuse/composition (§4): `Button` reused unchanged (`primary` for Play mirroring "New Project", default for Stop mirroring "Save"/"Open"); the position readout is trivial inline markup, correctly not promoted to a catalog component absent repeated use or a real interaction contract. Semantic tokens (§4/§5): only existing Tailwind utilities already mapped to `tokens.css`'s custom properties are used (`text-text-muted`, `bg-accent`) — no hardcoded values. Dark/light (§3/§5): inherited automatically from the same token system FT-025 already proved works in both themes; no new light-only value introduced. Geometry/motion (§3/§5): the status dot is static (no pulse/animation), consistent with "motion serves comprehension, not decoration"; `rounded-full` on an 8px status dot is a distinct affordance from the pill-heavy button/card styling the principle actually warns against. Component-catalog impact (§4): none — no new or modified catalog component.

**Accessibility (§3/§5) — one real gap found and fixed before Close:** the only signal of a Play/Stop state transition was each button's own `disabled` attribute flipping, which is not reliably announced by assistive tech on its own, and the fast-ticking (200ms) position text risked being wired as a noisy `aria-live` region if handled carelessly. Fixed by adding a separate `role="status"` element carrying just "Playing"/"Stopped" (an implicit `aria-live="polite"` region that changes only on real state transitions, not every tick), while the numeric position stays plain, non-live text — available to a screen reader on demand without being auto-announced every 200ms. The decorative dot keeps `aria-hidden="true"`, since the status text already conveys the same information non-visually.

### Validate

`npm run build` (tsc + vite, clean), `npm run lint` (oxlint, clean), `npm run test` (1 passed) all pass after the accessibility fix. `npm run tauri dev` was launched directly and confirmed via its own log to build cleanly and connect the Desktop channel sidecar successfully — real evidence beyond a mocked test — but this session's sandbox lacks the macOS Accessibility/Screen Recording permissions needed to visually drive or screenshot the actual native window (`osascript`/`screencapture` both refused), consistent with why every prior UI confirmation in this project's history (FT-025, FT-010, EP-005) has been performed by the human via `npm run tauri dev` rather than by Claude. The real click-through (New Project → Add Track → Add Clip → Play → hear audio, watch the playhead → Stop) and audible confirmation remain FT-030's own pending human-evidence item, per its Acceptance criteria.
